# Lust

**Rust + Lua + ECS + MCP.** Основа для программ, логика которых написана на Lua.

[English](README.md) | Русский

Lust даёт программе сразу четыре вещи, уже работающие вместе:

- **Lua в песочнице** — быстро (внизу Rust) и безопасно. Песочница — это закрытая среда:
  скрипт не может трогать файлы, систему и чужие запуски, и у него есть лимит времени и
  памяти.
- **Родная ECS** — один мир из сущностей и компонентов (ECS — схема «сущности и
  компоненты»). Правила тоже лежат в нём, как код на Lua, хранящийся как данные, поэтому их
  можно менять, пока программа работает.
- **Роли с правами и журнал** — каждая запись проверяется по правам роли, неудачный запуск
  откатывается целиком, а каждое изменение — запись в цепочке хешей.
- **Дверь для ИИ (MCP)** — ИИ-клиент видит, что может делать его роль, и предлагает;
  подтверждает только человек.

Поверх этого программа добавляет **свой API для Lua**. Игровой движок в духе LÖVE добавит
рисование и ввод, ERP — документы и страницы, симуляция — свои часы. Трудная общая часть
(песочница, мир, права, журнал, ИИ) уже готова.

**Состояние: версия 0.1.0, молодая.** Около 2500 строк, 34 теста. Интерфейс (API) ещё
может измениться.

## Попробовать

```
cargo run --example hello     # 30 строк: один тип, одна роль, одна операция, журнал
cargo run --example kiosk     # правило, отчёт, откат неудачного запуска, сохранение и проигрывание
cargo run --example engine    # крошечный движок: свои screen.print и ecs.now, игровой цикл
cargo run --example door      # ИИ через MCP: видит свои операции, предлагает, человек подтверждает
cargo run --example save      # сохранение и загрузка игры: запустите дважды, игра продолжится; "-- new" начинает заново
cargo build --example stdio   # MCP-сервер для настоящего ИИ-клиента через stdio (см. ниже)
cargo test
```

```rust
use lust::host::Host;

let host = Host::new()?;
{
    let mut w = host.world.borrow_mut();
    w.current_role = String::from("dev");
    w.set("hits", "kind", "int")?;                 // тип компонента — тоже сущность
    w.set("hits", "write", "dev guest")?;          // кто может писать
    w.set("role.guest", "desc", "may only knock")?;
    w.set("op.knock", "roles", "guest")?;          // кто может выполнять операцию
    w.set("op.knock", "src", "return function()
        ecs.set('door', 'hits', (ecs.get('door', 'hits') or 0) + 1)
    end")?;
}
host.run("guest", "knock", &[])?;                  // теперь door.hits равно 1
```

(Это сокращённый вариант. Полный проверенный лежит в `examples/hello.rs`: там ещё
объявлены типы `roles`, `params` и `src`, которые нужны операциям.)

## Мир (`src/ecs.rs`)

- **Сущность** — просто имя (`door`, `op.knock`, `role.guest`).
- **Компонент** — таблица «сущность → значение». У всех записей одного компонента одни и
  те же права. Поэтому мир хранится по компонентам.
- **Типы компонентов тоже сущности.** Сущность `hits` с компонентами `kind = int` и
  `write = dev guest` описывает компонент `hits`. Типы, код и данные разработчик меняет
  одними и теми же вызовами.
- **Виды значений**, проверяются при каждой записи: `text`, `code`, `int`, `bool`, `ref`
  (имя существующей сущности), `name`, `names` (несколько имён через пробел).
- **Два расширения обычной ECS:** `is_a` (сущность берёт значения у своего прототипа, если
  своих нет; прототип — это сущность-шаблон) и `parent` (тип компонента с родителем
  принадлежит этой сущности: его можно задавать только ей, её детям и их экземплярам).
- **Права:** `write` перечисляет роли, которым можно писать компонент. Встроенная роль
  `core` пишет первые записи, и ни один скрипт не может ею воспользоваться.
- **Приватные значения:** тип компонента с `local_ai = true` читается как пустой, пока мир
  показывают читателю, которому его видеть нельзя (`World::hide_private`), например ИИ в
  облаке.
- **Пределы:** 200 000 сущностей, 2 000 000 значений, имя до 64 символов, текст до 4000,
  код до 64 КБ.

## Код (`src/host.rs`)

Код сущности лежит в её компоненте `src` и возвращает функцию. Использовать его можно
четырьмя способами, по соглашению об именах:

| Сущность | Что это | Когда выполняется |
|---|---|---|
| `op.<имя>` | **операция**: что может делать роль (`roles`, `params`, `desc`) | когда роль вызывает `host.run` |
| `sys.<имя>` с `system = true` | **правило**: идёт от роли `system`, в порядке `ord` | после каждой операции |
| `view.<имя>` | **отчёт**: только чтение, возвращает таблицу (как JSON) | когда его запрашивают |
| любой другой `src` | общий код, доступный через `ecs.call` | когда его вызывают |

**Операция и её правила — одно целое.** Если в любом месте что-то упало, всё, что она
успела сделать, откатывается, а журнал записывает причину. Аргументы проверяются до
запуска (`id`, `int`, `text`, `long`).

**Права роли действуют и внутри кода.** Если операция кладовщика пытается записать
компонент, который кладовщику писать нельзя, запуск падает с ошибкой `no_right`.

**Песочница** — это Lua 5.4 только с библиотеками `table`, `string`, `math` и `utf8`. Нет
`io`, `os`, `require`, `load`, `pcall` и `getmetatable`, а `setmetatable` отказывает
метатаблице с `__gc` (такой «финализатор» сработал бы позже, вне своего запуска). Шаблоны
Lua (`string.find`, `match`, `gsub`) убраны: один вызов с ними может работать минутами.
Вместо них есть `string.find_plain`. У каждого запуска есть лимит времени (по умолчанию
250 мс, меняется через `budget.set_run_ms`) и лимит памяти (16 МБ). Ничто из того, что
скрипт оставил в глобальных переменных, не переживает запуск: каждый запуск начинается со
свежих копий.

**API для Lua** — одна таблица `ecs`:

| Вызов | Что делает |
|---|---|
| `ecs.get(e, c)` | значение: у самой сущности или по цепочке прототипов |
| `ecs.own(e, c)` | только собственное значение сущности |
| `ecs.set(e, c, v)` | запись; при любом отказе поднимает ошибку, запуск откатывается |
| `ecs.del(e, c)` | убрать собственное значение |
| `ecs.kill(e)` | удалить сущность |
| `ecs.spawn(id, {comp = value, ...})` | создать сущность |
| `ecs.instantiate(prefab, id)` | сделать `id` (и его детей) экземпляром прототипа |
| `ecs.with(c [, v])` | отсортированные сущности, у которых есть компонент `c` (равный `v`) |
| `ecs.children(e)`, `ecs.exists(e)`, `ecs.comps(e)`, `ecs.kind(c)` | осмотреться |
| `ecs.call(entity, arg)` | выполнить код другой сущности (верх файла только читает, права те же) |
| `ecs.history(e, n)`, `ecs.journal(n)` | последние изменения (n не больше 50) |
| `ecs.role()` | роль, от имени которой идёт запуск |

## Свой API (для движка, ERP, чего угодно)

Программа на Lust добавляет к тому, что видят скрипты, — до запусков или между ними:

- `host.add_global(name, value)` — новая глобальная переменная, например таблица `screen`
  с функциями, как в LÖVE есть `love.graphics`.
- `host.add_to_ecs(name, function)` — ещё одна функция в таблице `ecs`.
- `host.lua()` — состояние Lua, чтобы создавать эти функции (Lust отдаёт связку с Lua
  наружу как `lust::mlua`). Там же программа хранит свои данные — вне мира и вне журнала:
  `lua.set_app_data(...)`, а в функции читает через `lua.app_data_ref::<T>()`.
- `Host::on_refusal(hook)` — что делать после отказа или неудачи операции (например,
  считать отказы по ролям).
- `World::overlay` — значения, которые читатель видит вместо хранимых, пока мир только
  читается (например, несколько экранов из одного мира).

Добавленное видно всем следующим запускам. Таблица копируется заново для каждого запуска,
поэтому один запуск не может изменить то, что получит следующий, а существующие имена
(`ecs`, библиотеки, вызовы `ecs`) заменить нельзя. Добавленная функция, которая меняет мир,
должна делать это через `World::set`, тогда права и журнал соблюдаются. `examples/engine.rs`
— крошечный движок такого рода: `screen.print`, `ecs.now` и игровой цикл.

## Журнал (`src/store.rs`)

Каждое изменение — одна запись: кто (роль), в какой операции, что изменено, новое
значение, хеш предыдущей записи и собственный хеш (SHA-256). Хеш — это короткий
«отпечаток» содержимого: любая правка меняет его. Записи образуют цепочку.

- `Store::append` дописывает новые записи в файл, по одной JSON-строке на запись.
- `World::replay` собирает мир из записей и проверяет всю цепочку. Изменённая, обрезанная
  или переставленная запись обнаруживается.
- **Чего цепочка не делает:** в ней нет секрета. Тот, кто может писать в файл, может
  переписать его с какой-то записи и заново посчитать хеши. Чтобы это заметить, храните
  хеш последней записи (`World::head`) где-нибудь отдельно или подписывайте его.
- Недописанная последняя строка отбрасывается с предупреждением. Старый журнал никогда не
  перезаписывается: `store::archive` откладывает его в сторону.
- Отказы и откаты тоже попадают в журнал, как записи, которые ничего не меняют.

**Сохранение и загрузка игры** — это только это и ничего больше (`examples/save.rs`): после
каждого хода `Store::append` дописывает новые записи, а хеш последней записи кладётся в
отдельный маленький файл; при запуске — `store::load`, `World::replay`, сверка этого хеша и
`Host::with_world`. Правила тоже лежат в журнале, поэтому сохранённая игра хранит те
правила, по которым в неё играли. Новая игра откладывает старое сохранение в сторону через
`store::archive`.

## Дверь для ИИ (`src/mcp.rs`)

MCP (Model Context Protocol) — общепринятый способ, которым ИИ-клиент пользуется
инструментами программы. Lust говорит на нём сам, но без собственного формата подсказок.
Три части, каждой можно пользоваться отдельно:

- **Протокол:** `mcp::handle` принимает одно сообщение JSON-RPC 2.0 и возвращает ответ
  (`initialize`, `ping`, `tools/list`, `tools/call`); `mcp::handle_text` делает то же для
  одной строки текста. Способ передачи выбирает программа (HTTP или stdio — по сообщению
  на строку), и инструменты тоже, через трейт `mcp::Tools` (трейт — это набор функций,
  которые программа обязуется предоставить).
- **Очередь предложений** (`mcp::Proposals`): ИИ предлагает операцию своей роли. Её сразу
  проверяют так, как если бы роль её выполняла (есть ли операция, есть ли право, верен ли
  каждый аргумент), и она ждёт. Только программа, то есть человек, вызывает `confirm`;
  тогда операция выполняется от имени этой роли и никогда с бо́льшими правами, а журнал
  помечает её `mcp <номер>`. **Инструмента «подтвердить» нет.** Есть пределы: сколько
  предложений ждёт, размер запроса, сколько решённых хранится.
- **Три готовых инструмента** над миром и ролью (`mcp::WorldTools`): `lust_ops` (операции,
  которые роль может предложить, с типами параметров), `lust_propose` и `lust_status`.
  Значений мира ИИ не видит: что ему знать, решает программа, добавляя свой инструмент.

**Настоящий ИИ-клиент через stdio** (`examples/stdio.rs`): клиент, например Claude Desktop,
сам запускает программу и говорит с ней по одному JSON-сообщению на строку; stdout занят
протоколом, а то, что читает человек, идёт в stderr. Человеку нужен свой канал, которого
нет у ИИ: в примере это текстовый файл решений (`yes 3`, `no 3`), лежащий там, куда ИИ
писать не может (клиент с инструментами для файлов иначе мог бы решить за человека).
Настоящая программа даёт человеку окно или страницу. Как подключить пример к клиенту,
написано в его начале.

**Её можно убрать.** По умолчанию она включена. Чтобы собрать без неё, подключите Lust с
`default-features = false`. Чтобы удалить из исходников: удалите `src/mcp.rs` и
`examples/door.rs` и `examples/stdio.rs`, строки `mcp` в `src/lib.rs` и блоки `[features]`, `[[example]] door` и
`[[example]] stdio` в `Cargo.toml`. Больше ничто в Lust её не использует.

## Чего в Lust нет

В Lust нет окна, графики, сети и страниц: это дело программы, построенной на нём, через её
собственный API. Нет и своего формата подсказок для ИИ.

## Построено на Lust

- **Radost** — ядро ERP с веб-интерфейсом и голосовым вводом, модами и своими
  инструментами для ИИ поверх двери Lust (карточки-подсказки в формате S-Card, входящие —
  то, что сказал человек, файлы). Её игры, например «Корпорация Болтики: 20 лет», —
  подпроекты Radost.

Программа подключает Lust как обычную зависимость Cargo:

```toml
[dependencies]
lust = { git = "https://github.com/darkfrei/Lust" }
```

## Сборка

Нужен набор инструментов Rust. При первой сборке компилируется Lua 5.4, поэтому нужен
компилятор C (в Windows — Visual Studio Build Tools, в Linux — `gcc` или `clang`).

```
cargo build --release
cargo test
```
