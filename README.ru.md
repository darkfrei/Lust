# Lust

**Rust + Lua + ECS + MCP.** Основа для программ, логика которых написана на Lua.

[English](README.md) | Русский

Lust даёт программе сразу пять вещей, уже работающих вместе:

- **Lua в песочнице** — быстро (внизу Rust) и безопасно. Песочница — это закрытая среда:
  скрипт не может трогать файлы и систему, и у него есть лимит времени и памяти.
- **Родная ECS** (схема «сущности и компоненты») — столько миров, сколько нужно программе, и
  все одного вида: сущности с именем или номером, компоненты как проверяемый текст или как
  числа в плотных столбцах. Правила тоже лежат в мире, как код на Lua, хранящийся как данные,
  поэтому их можно менять, пока программа работает.
- **Что хранит мир — его выбор** (`Spec`, настройки мира): журнал (каждое изменение — запись в
  цепочке хешей), роли с правами, откат неудачного запуска, Lua, которая помнит между тиками.
  Учётная система или пошаговая игра хранит многое; аркада — ничего, кроме сохранения.
- **Дверь для ИИ (MCP)** — ИИ-клиент видит, что может делать его роль, и предлагает;
  подтверждает только человек.
- **Программа как папка Lua-файлов** (`lust dev <папка>`) — ИИ строит игру или инструмент
  через MCP, пишет только Lua-файлы, Rust не трогает. Каждая правка горячая (мир сохраняет
  значения, новый код работает со следующего такта), а человек смотрит на результат в
  браузере. См. [docs/dev.ru.md](docs/dev.ru.md).

Поверх этого программа добавляет **свой API для Lua**. Игровой движок в духе LÖVE добавит
рисование и ввод, ERP — документы и страницы, симуляция — свои часы. Трудная общая часть
(песочница, миры, права, журнал, ИИ) уже готова.

**Состояние: версия 0.1.0, молодая.** Около 7200 строк, 69 тестов. Интерфейс (API) ещё
может измениться.

## Попробовать

```
cargo run --example hello     # 30 строк: один тип, одна роль, одна операция, журнал
cargo run --example kiosk     # правило, отчёт, откат неудачного запуска, сохранение и проигрывание
cargo run --example engine    # крошечный движок: свои screen.print и ecs.now, игровой цикл
cargo run --example door      # ИИ через MCP: видит свои операции, предлагает, человек подтверждает
cargo run --release --example save       # учётный мир со счётом: снимки и тома журнала; запустите снова — продолжится
cargo run --release --example arkanoid   # игровой мир: без журнала и ролей, плавающий dt, сохранение и загрузка посреди игры
cargo run --release --example battle     # королевство (учётный мир) и мир на каждую битву: её итог — одна операция
cargo run --release --example frames     # сколько стоит тик: среднее, p99, худший
cargo build --example stdio   # MCP-сервер для настоящего ИИ-клиента через stdio (см. ниже)
cargo test

cargo build --release                           # программа lust
target/release/lust run examples/pong           # Pong, собранный ИИ через MCP: http://127.0.0.1:8730
target/release/lust dev <папка>                 # MCP-сервер: ИИ строит в этой папке
```

```rust
use lust::host::Host;

let host = Host::new()?;                           // учётный мир: журнал, роли, откат
{
    let mut w = host.world.borrow_mut();
    w.current_role = String::from("dev");
    w.set("hits", "kind", "int")?;                 // тип компонента — тоже сущность
    w.set("hits", "write", "dev guest")?;          // кто может его писать
    w.set("role.guest", "desc", "may only knock")?;
    w.set("op.knock", "roles", "guest")?;          // кто может выполнить эту операцию
    w.set("op.knock", "src", "return function()
        ecs.set('door', 'hits', (ecs.get('door', 'hits') or 0) + 1)
    end")?;
}
host.run("guest", "knock", &[])?;                  // теперь door.hits = 1
```

(Сокращено. `examples/hello.rs` — полная проверенная версия; там же объявлены типы
`roles`, `params` и `src`, нужные операциям.) Игровой мир — это
`Host::with_spec(Spec::game())`; см. `examples/arkanoid.rs`.

## Миры и что они хранят (`src/ecs.rs`, `Spec`)

Все миры одного вида; их `Spec` говорит, что мир хранит:

| Настройка | `Spec::ledger()` | `Spec::game()` |
|---|---|---|
| `journal`: каждое изменение — запись в цепочке хешей | да | нет |
| `roles`: права на каждый компонент и каждую операцию | да | нет |
| `undo`: неудачная операция или тик откатывается целиком | да | нет |
| `keep_lua`: глобальные переменные Lua живут от запуска к запуску | нет | да |

Любое сочетание допустимо (`Spec { journal: false, ..Spec::ledger() }`). Программа создаёт
столько миров, сколько ей нужно (`Host::with_spec`), и удаляет их, когда хочет. Один мир
передаёт другому итог только как одну операцию роли (`link.rs`). Модель, замеры и то, что ещё
остаётся проблемой: [docs/worlds.ru.md](docs/worlds.ru.md).

## Мир (`src/ecs.rs`)

- У **сущности** есть имя (`door`, `op.knock`, `role.guest`) и номер (`ecs.id`: индекс и
  поколение, так что старый номер никогда не достаётся новой сущности). Сущность, созданная без
  имени, называется `#1`, `#2`, ...
- **Компонент** — таблица «сущность → значение». У всех записей одного компонента одни и
  те же права. Поэтому мир хранится по компонентам.
- **Типы компонентов — тоже сущности.** Сущность `hits` с компонентами `kind = int` и
  `write = dev guest` описывает компонент `hits`. Разработчик меняет типы, код и данные одними
  и теми же вызовами.
- **Виды значений**: `text`, `code`, `int`, `bool`, `ref` (имя существующей сущности), `name`,
  `names` (несколько имён через пробел) — все проверяются при каждой записи и попадают в журнал
  мира, который его ведёт; и `num` — число (`f64`) в плотном столбце, никогда не в журнале, для
  того, что меняется каждый тик (координаты, скорости, здоровье).
- **Два дополнения к обычной ECS:** `is_a` (сущность берёт значения своего префаба, если у
  неё нет своих; префаб — сущность-шаблон) и `parent` (тип компонента, у которого есть
  родитель, принадлежит этой сущности: его можно задать только ей, её детям и их экземплярам).
- **Права** (в мире с ролями): `write` перечисляет роли, которые могут писать компонент.
  Встроенная роль `core` пишет первые записи, и ни один скрипт ей воспользоваться не может.
- **Откат** (в мире с откатом): запуск (`World::begin`), который не удался
  (`World::rollback`), возвращает каждое изменённое значение, текстовое и `num`, и каждую
  сущность, которую он создал или удалил.
- **Скрытые значения:** тип компонента с пометкой `local_ai = true` читается как пустой,
  пока мир показывают читателю, которому его видеть нельзя (`World::hide_private`), например
  ИИ в облаке.
- **Пределы** (учётный мир; у игрового больше): 200 000 сущностей, 2 000 000 значений, имена
  до 64 символов, текст до 4000, код до 64 КБ.

## Код (`src/host.rs`)

Код сущности лежит в её компоненте `src` и возвращает функцию. Пять способов его
использовать, все по соглашению об именах:

| Сущность | Что это | Когда выполняется |
|---|---|---|
| `op.<name>` | **операция**: что может делать роль (`roles`, `params`, `desc`) | когда программа вызывает `host.run` (ввод, ход, команда) |
| всё, у чего `system = true` | **правило**: от имени роли `system`, в порядке `ord` | после каждой операции |
| всё, у чего `tick = true` | **тик**: от имени роли `system`, в порядке `ord`, с `dt` | когда программа вызывает `host.tick(dt)` |
| `view.<name>` | **отчёт**: только чтение, возвращает таблицу (в JSON) | по запросу |
| любой другой `src` | общий код, вызывается через `ecs.call` | когда вызван |

`dt` — то, что передаёт программа: время с прошлого кадра или фиксированный шаг.
`clock::Clock` умеет оба (`Clock::variable(max_dt)`, `Clock::fixed(step, max_steps)`).

**Операция и её правила — одно целое.** В мире с откатом, если что-то в ней не удалось,
откатывается всё, что она сделала, а журнал записывает почему. Аргументы проверяются до
запуска (`id`, `int`, `text`, `long`).

**Права роли действуют и внутри кода.** Если операция кассира пытается записать
компонент, который кассиру писать нельзя, запуск падает с `no_right`.

**Песочница** — это Lua 5.4 только с библиотеками `table`, `string`, `math` и `utf8`. Нет
`io`, `os`, `require`, `load`, `pcall` и `getmetatable`, а `setmetatable` отказывает
метатаблице с `__gc` (такой «финализатор» сработал бы позже, вне своего запуска). Шаблоны
Lua (`string.find`, `match`, `gsub`) убраны: один вызов с ними может работать минутами.
Вместо них есть `string.find_plain`. У каждого запуска есть лимит времени (по умолчанию
250 мс, меняется через `budget.set_run_ms`) и лимит памяти (`Spec::memory`). Код
компилируется один раз и хранится, пока его текст не изменился.

**Без `keep_lua`** (учётный мир) ничто из того, что скрипт оставил в глобальных переменных, не
переживает запуск: каждый запуск начинается со свежих копий, а верх куска кода — только для
чтения. **С `keep_lua`** (игра) глобальные переменные живут дальше, как в игровом цикле, а верх
куска кода — его загрузка: выполняется один раз (снова, когда код изменился), может создать
первые сущности и задать глобальные переменные.

**API для Lua** — одна таблица `ecs` в каждом мире. Сущность — имя или номер, компонент `num`
— имя или номер столбца (`ecs.col`, быстрее):

| Вызов | Что делает |
|---|---|
| `ecs.get(e, c)` | значение — своё или из цепочки префабов |
| `ecs.own(e, c)` | только собственное значение сущности |
| `ecs.set(e, c, v)` | записать; при любом отказе — ошибка, и запуск откатывается (с откатом) |
| `ecs.del(e, c)` | удалить собственное значение |
| `ecs.kill(e)` | удалить сущность |
| `ecs.spawn(id, {c = v, ...})`, `ecs.spawn({c = v, ...})` | создать сущность, с именем или без; возвращает её номер |
| `ecs.id(e)`, `ecs.name(e)`, `ecs.col(c)`, `ecs.count([c])` | номера, имена, количества |
| `ecs.instantiate(prefab, id)` | сделать `id` (и его детей) экземпляром префаба |
| `ecs.with(c [, v])` | отсортированные сущности с компонентом `c` (равным `v`) |
| `ecs.children(e)`, `ecs.exists(e)`, `ecs.comps(e)`, `ecs.kind(c)` | осмотреться |
| `ecs.query(c, ...)` | `n, ids, vals, ...`: сущности, у которых есть все эти компоненты `num`, одним вызовом |
| `ecs.read(c, ids, vals)`, `ecs.write(c, ids, vals [, n])` | целый столбец `num` наружу и обратно, по одному вызову |
| `ecs.add(dst, src [, k])`, `ecs.scale`, `ecs.fill`, `ecs.clamp`, `ecs.sum` | целый столбец сразу |
| `ecs.run(name [, arg])` | система на Rust, которую добавила программа (`host.add_system`) |
| `ecs.commit({key = value, ...})` | итог для программы, чтобы передать его другому миру |
| `ecs.call(entity, arg)` | выполнить код другой сущности (с теми же правами) |
| `ecs.history(e, n)`, `ecs.journal(n)` | последние изменения (n не больше 50), в мире с журналом |
| `ecs.role()`, `ecs.tick()` | роль, от имени которой идёт запуск; сколько тиков было у мира |

На 10 000 сущностей один тик стоит около 1 мс через `query`, цикл в Lua и `write`, 0,006 мс
через `ecs.add` или систему на Rust и около 3 мс поштучно. Подробнее —
[docs/worlds.ru.md](docs/worlds.ru.md).

## Свой API (для движка, ERP, чего угодно)

Программа на Lust добавляет к тому, что видят скрипты, — до запусков или между ними:

- `host.add_global(name, value)` — новая глобальная переменная, например таблица `screen`
  с функциями, как в LÖVE есть `love.graphics`.
- `host.add_to_ecs(name, function)` — ещё одна функция в таблице `ecs`.
- `host.add_system(name, f)` — функция на Rust над столбцами мира (`World::column_mut`); из
  Lua — `ecs.run(name, arg)`. Это собственный код программы: он пишет в обход прав, отката и
  пределов.
- `host.lua()` — состояние Lua, чтобы создавать эти функции (Lust отдаёт связку с Lua
  наружу как `lust::mlua`). Там же программа хранит свои данные — вне мира и вне журнала:
  `lua.set_app_data(...)`, а в функции читает через `lua.app_data_ref::<T>()`.
- `Host::on_refusal(hook)` — что делать после отказа или неудачи операции (например,
  считать отказы по ролям).
- `World::overlay` — значения, которые читатель видит вместо хранимых, пока мир только
  читается (например, несколько экранов из одного мира).

Добавленное видно всем следующим запускам. В мире без `keep_lua` таблица копируется заново для
каждого запуска, поэтому один запуск не может изменить то, что получит следующий; существующие
имена (`ecs`, библиотеки, вызовы `ecs`) заменить нельзя. Добавленная функция, которая меняет
мир, должна делать это через `World::set`, тогда права и журнал соблюдаются.
`examples/engine.rs` — крошечный движок такого рода: `screen.print`, `ecs.now` и игровой цикл.

## Журнал — модуль (`src/journal.rs`, `src/store.rs`)

Мир ведёт журнал, если в его настройках есть `journal`. Тогда каждое изменение — одна запись:
кто (роль), в какой операции, что изменено, новое значение, хеш предыдущей записи и свой хеш
(SHA-256). Записи образуют цепочку. Значения `num` в неё не попадают никогда.

- `Store::append` дописывает новые записи в файл, по строке JSON на запись.
- `World::replay` собирает мир заново из записей и проверяет всю цепочку. Изменённая,
  обрезанная или переставленная запись обнаруживается.
- **Чего цепочка не делает:** у неё нет секрета. Кто может писать файл, тот может
  переписать его с какой-то записи и пересчитать хеши. Чтобы это заметить, храните хеш
  последней записи (`World::head`) где-то ещё или подписывайте его.
- Недописанная последняя строка отбрасывается с предупреждением. Старый журнал никогда не
  перезаписывается: `store::archive` откладывает его в сторону.
- Отказы и откаты тоже лежат в журнале — как записи, которые ничего не меняют.

**Сохранение и загрузка.** **Снимок** хранит всё состояние (`World::snapshot`,
`store::save_snapshot`): текстовые значения и `num`, имена сущностей без имени — со своим
хешем, так что снимок, изменённый вручную, отвергается. Игровой мир сохраняет только снимки и
загружает их через `World::from_snapshot_spec(spec, &snapshot, Vec::new())`
(`examples/arkanoid.rs`). Глобальные переменные Lua мира не сохраняются: что должно пережить
сохранение, лежит в компонентах; после загрузки верх каждого куска кода выполняется снова.

Учётный мир, который много считает (`examples/save.rs`, 40 тел притягивают друг друга каждый
тик), время от времени делает снимок и ведёт **том журнала** — записи после этого снимка. Они
продолжают ту же цепочку хешей. При каждом снимке старый том откладывается в сторону
(`store::archive`): история хранится, но для загрузки не нужна. Загрузка — это
`store::load_snapshot`, `store::load` тома и `World::from_snapshot(снимок, записи)`. Хеш
последней записи, хранящийся в отдельном файле, показывает сохранение, обрезанное или
переписанное вне игры. Правила лежат в мире, поэтому сохранённая игра хранит те правила, по
которым в неё играли.

## Из одного мира в другой (`src/link.rs`)

Миры независимы. Мир что-то считает (битву, ход ИИ, сцену с физикой) и отдаёт итог
(`ecs.commit{...}`); программа его забирает (`host.take_result()`) и выполняет в другом мире как
одну операцию роли (`link::commit_to`): она проверяется как любая другая операция и пишется в
журнал того мира, если журнал там есть. `Seed` помнит, что считающий мир прочитал из другого
при создании; если это за время счёта изменилось, итог отклоняется как устаревший.
`examples/battle.rs`: битва примерно 1100 солдат, 3308 тиков, 4 записи в журнале королевства.

## Программа как папка (`lust dev`, `src/project.rs`)

Программа `lust` (`src/bin/lust.rs`) запускает папку Lua-файлов: `world.lua` (начало: типы и
сущности), `sys/*.lua` (системы), `draw/*.lua` (рисование), `op/*.lua` (операции),
`view/`, `rule/`, `lib/` и `test/*.lua` (тесты). `lust dev <папка>` — MCP-сервер через
stdio: ИИ читает одну справку, пишет и правит файлы, пробует код на свежем мире, гоняет
тесты и откатывает изменения. Правка горячая: код, который не компилируется, отклоняется;
код, который компилируется, заменяет старый со следующего такта; значения остаются. Человек
видит живой мир в браузере (`src/web.rs`, это модуль: его можно заменить другим способом
показа). Pong, собранный так с пустой папки, занял 11 MCP-сообщений и около 3 000 токенов
содержимого. Подробно: [docs/dev.ru.md](docs/dev.ru.md).

## Дверь для ИИ (`src/mcp.rs`)

MCP (Model Context Protocol) — общепринятый способ, которым ИИ-клиент пользуется
инструментами программы. Lust говорит на нём сам, но без собственного формата подсказок.
Три части, каждой можно пользоваться отдельно:

- **Протокол:** `mcp::handle` принимает одно сообщение JSON-RPC 2.0 и возвращает ответ
  (`initialize`, `ping`, `tools/list`, `tools/call`); `mcp::handle_text` делает то же для
  одной строки текста. Способ передачи выбирает программа (HTTP или stdio — по сообщению
  на строку), и инструменты тоже, через трейт `mcp::Tools` (трейт — это набор функций,
  которые программа обязуется предоставить).
- **Очередь предложений** (`mcp::Proposals`): ИИ предлагает операцию своей роли. Её сразу
  проверяют так, как если бы роль её выполняла (есть ли операция, есть ли право, верен ли
  каждый аргумент), и она ждёт. Только программа, то есть человек, вызывает `confirm`;
  тогда операция выполняется от имени этой роли и никогда с бо́льшими правами, а журнал
  помечает её `mcp <номер>`. **Инструмента «подтвердить» нет.** Есть пределы: сколько
  предложений ждёт, размер запроса, сколько решённых хранится.
- **Три готовых инструмента** над миром и ролью (`mcp::WorldTools`): `lust_ops` (операции,
  которые роль может предложить, с типами параметров), `lust_propose` и `lust_status`.
  Значений мира ИИ не видит: что ему знать, решает программа, добавляя свой инструмент.

**Настоящий ИИ-клиент через stdio** (`examples/stdio.rs`): клиент, например Claude Desktop,
сам запускает программу и говорит с ней по одному JSON-сообщению на строку; stdout занят
протоколом, а то, что читает человек, идёт в stderr. Человеку нужен свой канал, которого
нет у ИИ: в примере это текстовый файл решений (`yes 3`, `no 3`), лежащий там, куда ИИ
писать не может (клиент с инструментами для файлов иначе мог бы решить за человека).
Настоящая программа даёт человеку окно или страницу. Как подключить пример к клиенту,
написано в его начале.

**Её можно убрать.** По умолчанию она включена. Чтобы собрать без неё, подключите Lust с
`default-features = false`. Чтобы удалить из исходников: удалите `src/mcp.rs`, `src/dev.rs`,
`src/bin/lust.rs`, `examples/door.rs` и `examples/stdio.rs`, строки `mcp` в `src/lib.rs` и
блоки `[features]`, `[[example]] door`, `[[example]] stdio` и `[[bin]] lust` в
`Cargo.toml`. Больше ничто в Lust её не использует.

## Чего в Lust нет

В Lust нет окна и сети дальше `127.0.0.1`. Его экран — простой 2D-кадр (прямоугольники,
круги, линии, текст), который показывает страница в браузере; программа, которой нужно
больше (картинки, звук, окно, страницы ERP), добавляет это своим API или своим модулем
показа. Нет и своего формата подсказок для ИИ.

## Построено на Lust

- **Radost** — ядро ERP с веб-интерфейсом и голосовым вводом, модами и своими
  инструментами для ИИ поверх двери Lust (карточки-подсказки в формате S-Card, входящие —
  то, что сказал человек, файлы). Её игры, например «Корпорация Болтики: 20 лет», —
  подпроекты Radost.

Программа подключает Lust как обычную зависимость Cargo:

```toml
[dependencies]
lust = { git = "https://github.com/darkfrei/Lust" }
```

## Сборка

Нужен набор инструментов Rust. При первой сборке компилируется Lua 5.4, поэтому нужен
компилятор C (в Windows — Visual Studio Build Tools, в Linux — `gcc` или `clang`).

```
cargo build --release
cargo test
```
