# Программа как папка Lua-файлов (`lust dev`)

[English](dev.md) | Русский

Lust — это ядро. Программа на нём — **папка Lua-файлов**: игра, инструмент, модуль ERP.
Чтобы её сделать, никому — ни человеку, ни ИИ — не нужно менять код на Rust. ИИ строит
программу через MCP, а человек смотрит в своём окне (или в браузере, с `--web`), как она
работает и растёт.

```
cargo build --release                      # получится target/release/lust (lust.exe в Windows)
lust dev  [<папка>] [--web] [--port 8730] [--fps 60] [--no-web] # MCP-сервер для ИИ и живой мир в окне
lust run  <папка> [--web] [--port 8730] [--fps 60]      # мир в окне (--web: в браузере)
lust test <папка>                                       # тесты папки
lust hear <файл.wav>                                    # какие слова распознаватель слышит в нём
```

Попробовать на Pong, который ИИ собрал только через MCP (ниже):

```
lust run examples/pong          # откроется окно, клавиши W/S или вверх/вниз
lust test examples/pong
```

## Как дать ИИ игры

Разрешение — это папка игр: папка `games` рядом с `lust` (создаётся, если её нет). ИИ пишет
туда Lua-файлы и больше никуда, Rust не трогает. Человек называет игру в чате («открой
bomberman» или новое имя), ИИ открывает её инструментом `lust_open`; новое имя создаёт
папку с пустым `world.lua`. Для другой игры в настройках ничего не меняется.

Claude Desktop (`claude_desktop_config.json`, Настройки, Developer, Edit Config) или любой
MCP-клиент, который запускает программу (на Windows этот текст пишет `lust-dev.bat`):

```json
{
  "mcpServers": {
    "lust": { "command": "C:\\tools\\lust.exe", "args": ["dev"] }
  }
}
```

Claude Code: `claude mcp add lust -- C:\tools\lust.exe dev`

`lust dev <папка>` тоже работает: папка одной игры запускается в этой игре (её игры — папка
вокруг неё), папка игр показывает их список.

**Окно появляется, когда ИИ работает.** Клиент ИИ запускает `lust dev` при собственном
старте, задолго до того как нужна игра, поэтому lust стартует без окна и ничего не показывает
(один простаивающий процесс, около 4 % одного ядра и 100 МБ). Окно появляется при первой работе
над игрой: `lust_open` с именем, `lust_write`, `lust_edit`, `lust_delete`, `lust_undo`,
`lust_restart`, `lust_pack`, `lust_listen` или `lust_show`. Чтение (`lust_guide`, `lust_files`,
`lust_read`, `lust_test`, `lust_try`, `lust_open` без имени) окно не показывает. Микрофон
включён, только пока окно показано.

**Одно окно.** Каждый клиент, который запускает `lust dev` (Claude Desktop, Claude Code,
ещё одно приложение), запускает свой lust. Первый открывает окно, микрофон и мир и ждёт
остальных на `127.0.0.1:8729` (хаб); следующий ничего не открывает и передаёт свои сообщения
первому. Поэтому окно и мир одни на всех. lust завершается, когда ушёл последний клиент.

## Папка

| Файл | Что это | Его сущность |
|---|---|---|
| `world.lua` | начало: spec, типы, именованные и безымянные сущности | |
| `sys/<n>.lua` | система: `return function(dt) ... end`, каждый такт | `sys.<n>`, `tick = true` |
| `draw/<n>.lua` | рисование, после тактов, только чтение | `draw.<n>`, `draw = true` |
| `op/<n>.lua` | операция: `return function(p) ... end` | `op.<n>` |
| `rule/<n>.lua` | правило, после каждой операции | `rule.<n>`, `system = true` |
| `view/<n>.lua` | представление: возвращает таблицу | `view.<n>` |
| `lib/<n>.lua` | общий код, доступ через `ecs.call('lib.<n>')` | `lib.<n>` |
| `test/<n>.lua` | тест: код драйвера на свежем мире | не в мире |
| `<n>.md` | заметки для ИИ и для людей | |

`<n>` — это `[a-z0-9_]`. Другие файлы не трогаются. `world.lua` — это Lua, так что
сущности можно строить циклами:

```lua
return {
  spec = 'game',   -- или 'ledger', или {journal = true, roles = false, undo = true, keep_lua = true}
  types = { x = 'num', y = 'num', stock = {kind = 'int', write = 'clerk system'} },
  entities = {
    ball = { x = 400, y = 300 },
    ['sys.ball'] = { ord = 2 },                              -- порядок систем
    ['op.sell'] = { params = 'item:id n:int', roles = 'clerk', desc = 'sells n' },
  },
  spawn = { {x = 1}, {x = 2} },                              -- безымянные сущности
}
```

Всё остальное (Lua API внутри файлов, драйвер, инструменты) собрано в одном тексте, который
ИИ читает один раз: `lust_guide`, константа `GUIDE` в `src/dev.rs`. Это и есть справочник.

## Правка горячая

Lua интерпретируется, поэтому ничего не перезапускается. Когда файл меняется:

- **код** (`sys/`, `draw/`, `op/`, ...): сначала компилируется; код, который не
  компилируется, отклоняется, и работает старый. Код, который компилируется, заменяет
  старый, и мир выполняет его со следующего такта. **Значения мира остаются**: мяч летит
  дальше. Верх файла выполняется заново (его локальные переменные начинаются сначала),
  поэтому состояние должно жить в компонентах.
- **`world.lua`**: применяется то, что в нём изменилось (добавленные, изменённые,
  удалённые значения и типы); остальное состояние остаётся. Новый `spec` или `spawn`
  требуют перезапуска.
- **удалённый файл кода**: его сущность теряет код и останавливается.

То же самое работает для файлов, которые человек правит в редакторе: `lust dev` и
`lust run` смотрят в папку дважды в секунду.

Мир, в котором случилась ошибка (в такте или в рисовании), останавливается, продолжает
показывать последний кадр и пишет на странице, где ошибка:
`tick 912: sys/ball.lua:23: attempt to ...`. Следующая правка запускает его снова.
`lust_restart` начинает его заново из `world.lua`.

## Инструменты ИИ (`src/dev.rs`)

| Инструмент | Что делает |
|---|---|
| `lust_open` | игра, которую назвал человек (папка в `games`; новое имя её создаёт); без имени: список |
| `lust_show` | показывает окно человеку (оно скрыто, пока ИИ не работает над игрой, и после того как человек его закрыл) |
| `lust_listen` | ждёт до 45 с слов человека (ниже) и отдаёт их |
| `lust_guide` | формат и все функции Lua, один раз |
| `lust_files` | файлы с числом строк, состояние живого мира, где его видит человек |
| `lust_read` | файл или его строки `from`..`to` |
| `lust_write` | файл целиком |
| `lust_edit` | замена точного текста: `old` (ровно одно вхождение) на `new`, или несколько `edits` |
| `lust_delete` | удалить файл |
| `lust_undo` | вернуть последние `n` изменений (и правки человека тоже) |
| `lust_restart` | живой мир заново из `world.lua` |
| `lust_try` | код драйвера на свежем мире или на живом (`live = true`) |
| `lust_test` | тесты `test/*.lua`, каждый на свежем мире |

Каждое сохранённое изменение сразу проверяется на свежем мире (один такт, один кадр), и
ответ говорит, как прошло. ИИ узнаёт об ошибке в том же ответе, с файлом и строкой, а не
находит её потом.

**Драйвер** (`src/driver.rs`) — отдельный Lua, который управляет миром снаружи:
`step(n, dt)`, `get`, `set`, `keys('up')`, `press('space')`, `mouse(x, y, down)`, `draw()`
(кадр текстом), `run(role, op, args)`, `view`, `ms()`, `print`. ИИ проверяет игру, которую
не видит: держит клавиши, делает шаги, читает значения и кадр.

**История** (`.lust/history` в папке): каждое изменение сохраняет то, что было до него,
последние 500. `lust_undo` возвращает их.

## Экран — это модуль (`src/screen.rs`, `src/web.rs`, `src/native`)

Ядро знает только **кадр как текст** и **ввод**:

```
size 800 600
clear #000
rect 25 255 10 90 #fff
circle 400 300 8 #ff0
text 330 20 40 #fff 3
```

Lua рисует через `gfx.size/clear/rect/circle/line/text` (только в файлах `draw/`) и читает
`input.down(key)`, `input.pressed(key)`, `input.mouse()`, `input.mic()` (громкость микрофона от 0 до 1; файл рисования просит её через `gfx.mic(true)`; окно или браузер показывает, что микрофон включён; в мир попадает только число). Модуль показа выводит кадр и
возвращает ввод через `Exchange` (мьютекс, Lua в нём нет).

`gfx.measure(text, size)` даёт ширину и высоту текста, где угодно (и в `sys/`). Браузер
(и окно) сообщает ширину своих моноширинных букв (`cw=`), поэтому ответ совпадает с тем, что
видно.
В каждый проект встроена `lib.ui` (`local ui = ecs.call('lib.ui')`): кнопки, которые знают
свои `w` и `h`, надписи, панели, расстановка `stack`/`row`, `menu`, `update_menu` (клавиши,
мышь, enter), `paragraph` (перенос текста по ширине). `examples/menu` это заготовка игры с
меню, игрой, настройками и страницей «о программе».

## Сохранения (`src/saves.rs`)

`ecs.save(slot)` и `ecs.load(slot)` выполняются после такта (загрузка возвращает `false`, если
такого слота нет); `ecs.slots()` даёт их список, `ecs.erase(slot)` удаляет. Слот это 1..32
символа из `a-z 0-9 _ -`, не больше 20 слотов по 4 МБ. Сохраняются только данные: код и типы
берутся из файлов, поэтому правка кода не ломает сохранение. Загрузка сверяется с типами игры
и отказывает с причиной в строке состояния, если тип исчез или стал другого вида. Сохранения
лежат в папке данных пользователя (`%APPDATA%\lust\<игра>` на Windows,
`~/.local/share/lust/<игра>` на других системах) под именем папки игры; упакованная игра
носит это имя с собой. Тесты и `lust_try` держат сохранения в памяти. `examples/menu`
сохраняет счёт и настройки.

## События и конец игры (`src/screen.rs`)

Кадр можно пропустить или получить дважды, а звук или конец игры должны случиться ровно один
раз. Поэтому у мира есть второй путь к экрану: события. Код такта создаёт событие (сейчас
`ecs.quit()`, позже звуки; не больше 16 за такт и никогда из файла `draw/`). Программа
нумерует события и хранит последние 64 в течение 5 секунд. Страница с каждым запросом
присылает номер последнего полученного события (`ack=`) и получает те, что после него; новая
страница (`ack=new`) старых не получает. `ecs.quit()` завершает программу, когда страница
услышала событие (или через секунду); страница сообщает, что игра закрыта. В `lust dev` мир
только встаёт на паузу, чтобы ИИ мог продолжать. В тесте `events()` отдаёт то, что мир
сообщил экрану с прошлого вызова.

## Когда страницу или окно закрыли

Закрытое окно сразу завершает `lust run` и двойной клик; окно `lust dev` только прячется (микрофон выключается, ИИ работает дальше; следующая его работа над игрой или `lust_show` показывает окно снова; выход из клиента ИИ завершает lust). Со страницей `lust run --web` и двойной клик ставят игру на паузу, пока её не показывает ни одна страница
(вкладка скрыта или браузер ещё не открылся), и завершаются, когда страницу закрыли (через
3 секунды, чтобы перезагрузка не считалась закрытием) или когда о странице не было слышно
3 минуты. `lust dev` продолжает работать: его завершает клиент ИИ. Игра, которая ничего не
рисует, показывает подсказку вместо чёрного экрана.

## Игра одним файлом (`lust_pack`, `src/pack.rs`)

Когда игра готова, ИИ вызывает `lust_pack` (или вы запускаете `lust pack <папка>`): получается
`<папка>/dist/<имя папки>` (на Windows `.exe`), то есть программа lust, к концу которой
приклеены lua-файлы папки. Двойной клик по этому файлу открывает игру сразу на её собственном
меню: без командной строки, без списка игр, без второго файла. При старте файл распаковывает
свои lua-файлы во временную папку и запускает их; чёрное окно двойного клика закрывается.
Размер около 14 МБ плюс файлы (с окном; 3 МБ без фичи `native`). Это тот же lust, поэтому для игры Rust не нужен.

## Запуск без командной строки

Двойной клик по `lust`: в окне появляется список игр рядом с ним (папки с `world.lua`
в папке `games` рядом с `lust`) в виде кнопок. Клик запускает игру, F1 возвращает к списку.
Папка игры, брошенная на `lust.exe`, запускает только эту игру. Если рядом с `lust` лежит
`world.lua`, запускается эта папка.

`web.rs` — один такой модуль: страница на `127.0.0.1` с canvas. Без зависимостей (только
std), отвечает только на запросы с `Host` равным `127.0.0.1` или `localhost` (чтобы чужая
веб-страница не добралась до мира через браузер), принимает не больше 4 КБ ввода за запрос.
Чтобы показывать мир иначе (например, в терминале), достаточно модуля, который читает
`Exchange::frame` и вызывает `Exchange::put_input`; остальное не меняется. Без фичи `web`
он не собирается. Окно ниже — второй такой модуль.

## Окно (`src/native`)

`lust run`, `lust dev` и двойной клик открывают игру в **своём окне**, без браузера (фича
`native`, включена по умолчанию). `--web` показывает её в браузере, как раньше; так же
поступает компьютер, где окно не открылось (нет видеокарты): lust пишет об этом и открывает
страницу. В `lust dev` ИИ работает через MCP как раньше; окно показывает игру, знак ИИ и микрофона и то,
что сказал человек; `--no-web` не показывает ничего (только ИИ, без голоса).

- Окно создаёт библиотека winit, она же читает клавиши и мышь; библиотека pixels выводит
  картинку через видеокарту (DirectX 12 или Vulkan на Windows). Это нужно для оверлея Steam:
  поверх картинки, нарисованной без видеокарты, он не появляется.
- Саму картинку рисует процессор (`src/native/draw.rs`): прямоугольник, круг, линия с мягкими
  краями, текст из растрового шрифта DejaVu Sans Mono (латиница, немецкие и русские буквы,
  около 300 знаков; остальные показываются как `?`). Кадр Pong 1920 x 1080 занимает около 4 мс.
- Окно разговаривает с миром так же, как страница (тот же текст ввода, те же события с
  `ack`), поэтому игра их не различает. Кадр сохраняет пропорции и стоит посередине окна;
  окно один раз принимает размер первого кадра.
- Окно рисует, когда мир выдал новый кадр (по умолчанию 60 в секунду), и не реже 10 раз в
  секунду, но не чаще: если видеокарта не ждёт монитор, процессор не тратится зря.
- Закрытие окна сразу завершает `lust run`; в `lust dev` окно только прячется (см. выше).
  `ecs.quit()` завершает `lust run`, как со страницей, и ставит на паузу `lust dev`. Свёрнутое
  окно ставит `lust run` на паузу. В заголовке окна имя открытой игры.
- **Микрофон** (`src/native/mic.rs`, библиотека cpal: WASAPI на Windows, ALSA на Linux)
  включён, пока кадры его просят (`gfx.mic(true)`, выключается через 1,5 с после последней
  просьбы, как на странице), а в `lust dev` всё время. В мир попадает только громкость (0..1);
  звук идёт только в распознаватель (ниже) и не хранится. Если микрофона нет или система его
  запретила (Windows: Параметры, Конфиденциальность, Микрофон), в углу написано почему, а
  `input.mic()` остаётся 0.
- **Знак** в правом верхнем углу — сквиркл (квадрат с круглыми боками): его рамка — это ИИ
  (серая: ИИ ещё нет, зелёная: подключён, голубая: ждёт ваших слов), середина — микрофон
  (красная, растёт, когда вы говорите; серая черта: выключен). Рядом надпись «AI connected» и
  т. п., под ней слова, которые сейчас слышны, потом сказанная фраза (6 с) или оранжевым —
  почему голоса нет.
- **Голос** (`src/native/voice.rs`): vosk (Apache 2.0) превращает речь в текст на этом
  компьютере, без интернета. В lust он не встроен: lust открывает `libvosk.dll` (на Linux
  `libvosk.so`) рядом с собой во время работы, и папку модели `vosk-model-...` рядом с собой
  или на одну папку глубже. Zip для Windows несёт dll; русская модель
  (`vosk-model-small-ru-0.22`, около 45 МБ) — это `lust-voice-ru.zip`. Когда человек просит
  ИИ слушать, ИИ вызывает `lust_listen`: тот ждёт до 45 с (клиент бросает вызов через минуту)
  и отдаёт фразы; ИИ их выполняет и вызывает снова, пока человек не скажет «стоп». Сказанное,
  пока никто не ждёт, хранится 90 с для следующего вызова. Фразы идут только к ИИ, в мир
  никогда. Без dll или модели lust работает как раньше, знак пишет, чего не хватает, и
  `lust_listen` тоже. `lust hear <файл.wav>` печатает, что vosk слышит в звуковом файле
  (сборка на GitHub проверяет голос файлом `tools/voice-check.wav`). Маленькая модель иногда
  ошибается (имена, быстрая речь): справка велит ИИ брать вероятный смысл и переспрашивать,
  если не уверен.
- У каждого окна свой `Exchange`, поэтому второе окно это второй `Exchange` (пока не сделано:
  в Lua нечем его попросить).
- Добавляет около 180 библиотек к сборке и около 11 МБ к программе (замерено на Linux, на
  Windows не замерено). На Linux для сборки нужен `libasound2-dev`. Без фичи `native` ничего
  из этого не собирается.

## Безопасность

- ИИ пишет только пути из таблицы выше, внутри папки: без `..`, без других расширений, не
  больше 64 КБ на файл и 2000 файлов.
- Lua мира и драйвера работает в песочнице Lust: нет `io`, `os`, `require`, `load`,
  `pcall`, нет строковых шаблонов; у каждого запуска свой бюджет времени и памяти. Запуск
  драйвера — до 20 с.
- Страница слушает только `127.0.0.1`. MCP идёт через stdio: с `lust dev` говорит только
  программа, которая его запустила, и хаб на `127.0.0.1:8729`, который принимает только
  другой lust dev (тот сначала здоровается). Программа на этом компьютере могла бы войти в хаб,
  как могла бы и сама запустить lust dev: разрешением по-прежнему служит папка игр.
- Инструмента, подтверждающего операцию роли (`src/mcp.rs`), по-прежнему нет. `lust dev` —
  для разработки, разрешением служит папка; готовая программа даёт ИИ дверь предложений.

## Сколько токенов (замер)

Pong, собранный с пустой папки только через MCP, одна и та же игра дважды:

| | раньше (один `put` на значение) | `lust dev` |
|---|---|---|
| сообщений | 101 | 11 |
| отправил ИИ | 8 839 символов | 4 099 |
| прочитал ИИ | 3 539 | 7 016, из них 6 645 один раз за сессию (список инструментов и справка) |
| исправление в две строки | файл целиком заново, ~1 500 | `lust_edit`, ~70 |
| результат | только числа, без картинки и клавиш | играется в браузере, есть тест |

Примерно 4 символа — один токен, так что вся игра обошлась примерно в 3 000 токенов
содержимого плюс накладные расходы 11 вызовов. Во втором прогоне код был верным с первого
раза (ошибки первого прогона были известны); ошибка теперь стоит один `lust_edit`, а ответ
уже называет файл и строку.

Один такт этого Pong занимает 0,0064 мс; ничего из стороны ИИ в кадре не выполняется.

## Ограничения (честно)

- Справка — около 1 100 токенов, читается раз за сессию; её можно сократить.
- Один проект — один мир. Несколько миров и связи между ними (`src/link.rs`) пока требуют
  Rust.
- Экран простой, 2D: прямоугольники, круги, линии, текст. Картинок и звука пока нет:
  каждое — ещё одна команда кадра и модуля показа.
- `lust dev` крутит мир в том же потоке, что и сообщения MCP: долгий `lust_try` (до 20 с)
  на это время задерживает живые кадры.
- Живой мир `lust dev` не сохраняется между сессиями (у игрового spec нет журнала).
