# Программа как папка Lua-файлов (`lust dev`)

[English](dev.md) | Русский

Lust — это ядро. Программа на нём — **папка Lua-файлов**: игра, инструмент, модуль ERP.
Чтобы её сделать, никому — ни человеку, ни ИИ — не нужно менять код на Rust. ИИ строит
программу через MCP, а человек смотрит в браузере, как она работает и растёт.

```
cargo build --release                      # получится target/release/lust (lust.exe в Windows)
lust dev  <папка> [--port 8730] [--fps 60] [--no-web]   # MCP-сервер для ИИ и живой мир
lust run  <папка> [--port 8730] [--fps 60]              # мир в браузере
lust test <папка>                                       # тесты папки
```

Попробовать на Pong, который ИИ собрал только через MCP (ниже):

```
lust run examples/pong          # затем открыть http://127.0.0.1:8730, клавиши W/S или вверх/вниз
lust test examples/pong
```

## Как дать ИИ папку

Разрешение — это сама папка. Человек выбирает её один раз, в настройках ИИ-клиента. ИИ
пишет туда Lua-файлы и больше никуда, Rust не трогает.

Claude Desktop (`claude_desktop_config.json`) или любой MCP-клиент, который запускает
программу:

```json
"mcpServers": {
  "pong": { "command": "C:\\tools\\lust.exe", "args": ["dev", "D:\\games\\pong"] }
}
```

Claude Code: `claude mcp add pong -- C:\tools\lust.exe dev D:\games\pong`

Папка должна существовать. Пока клиент работает, человек открывает адрес, который печатает
`lust dev` (по умолчанию `http://127.0.0.1:8730`), и видит, как мир меняется с каждой
правкой.

## Папка

| Файл | Что это | Его сущность |
|---|---|---|
| `world.lua` | начало: spec, типы, именованные и безымянные сущности | |
| `sys/<n>.lua` | система: `return function(dt) ... end`, каждый такт | `sys.<n>`, `tick = true` |
| `draw/<n>.lua` | рисование, после тактов, только чтение | `draw.<n>`, `draw = true` |
| `op/<n>.lua` | операция: `return function(p) ... end` | `op.<n>` |
| `rule/<n>.lua` | правило, после каждой операции | `rule.<n>`, `system = true` |
| `view/<n>.lua` | представление: возвращает таблицу | `view.<n>` |
| `lib/<n>.lua` | общий код, доступ через `ecs.call('lib.<n>')` | `lib.<n>` |
| `test/<n>.lua` | тест: код драйвера на свежем мире | не в мире |
| `<n>.md` | заметки для ИИ и для людей | |

`<n>` — это `[a-z0-9_]`. Другие файлы не трогаются. `world.lua` — это Lua, так что
сущности можно строить циклами:

```lua
return {
  spec = 'game',   -- или 'ledger', или {journal = true, roles = false, undo = true, keep_lua = true}
  types = { x = 'num', y = 'num', stock = {kind = 'int', write = 'clerk system'} },
  entities = {
    ball = { x = 400, y = 300 },
    ['sys.ball'] = { ord = 2 },                              -- порядок систем
    ['op.sell'] = { params = 'item:id n:int', roles = 'clerk', desc = 'sells n' },
  },
  spawn = { {x = 1}, {x = 2} },                              -- безымянные сущности
}
```

Всё остальное (Lua API внутри файлов, драйвер, инструменты) собрано в одном тексте, который
ИИ читает один раз: `lust_guide`, константа `GUIDE` в `src/dev.rs`. Это и есть справочник.

## Правка горячая

Lua интерпретируется, поэтому ничего не перезапускается. Когда файл меняется:

- **код** (`sys/`, `draw/`, `op/`, ...): сначала компилируется; код, который не
  компилируется, отклоняется, и работает старый. Код, который компилируется, заменяет
  старый, и мир выполняет его со следующего такта. **Значения мира остаются**: мяч летит
  дальше. Верх файла выполняется заново (его локальные переменные начинаются сначала),
  поэтому состояние должно жить в компонентах.
- **`world.lua`**: применяется то, что в нём изменилось (добавленные, изменённые,
  удалённые значения и типы); остальное состояние остаётся. Новый `spec` или `spawn`
  требуют перезапуска.
- **удалённый файл кода**: его сущность теряет код и останавливается.

То же самое работает для файлов, которые человек правит в редакторе: `lust dev` и
`lust run` смотрят в папку дважды в секунду.

Мир, в котором случилась ошибка (в такте или в рисовании), останавливается, продолжает
показывать последний кадр и пишет на странице, где ошибка:
`tick 912: sys/ball.lua:23: attempt to ...`. Следующая правка запускает его снова.
`lust_restart` начинает его заново из `world.lua`.

## Инструменты ИИ (`src/dev.rs`)

| Инструмент | Что делает |
|---|---|
| `lust_guide` | формат и все функции Lua, один раз |
| `lust_files` | файлы с числом строк, состояние живого мира, где его видит человек |
| `lust_read` | файл или его строки `from`..`to` |
| `lust_write` | файл целиком |
| `lust_edit` | замена точного текста: `old` (ровно одно вхождение) на `new`, или несколько `edits` |
| `lust_delete` | удалить файл |
| `lust_undo` | вернуть последние `n` изменений (и правки человека тоже) |
| `lust_restart` | живой мир заново из `world.lua` |
| `lust_try` | код драйвера на свежем мире или на живом (`live = true`) |
| `lust_test` | тесты `test/*.lua`, каждый на свежем мире |

Каждое сохранённое изменение сразу проверяется на свежем мире (один такт, один кадр), и
ответ говорит, как прошло. ИИ узнаёт об ошибке в том же ответе, с файлом и строкой, а не
находит её потом.

**Драйвер** (`src/driver.rs`) — отдельный Lua, который управляет миром снаружи:
`step(n, dt)`, `get`, `set`, `keys('up')`, `press('space')`, `mouse(x, y, down)`, `draw()`
(кадр текстом), `run(role, op, args)`, `view`, `ms()`, `print`. ИИ проверяет игру, которую
не видит: держит клавиши, делает шаги, читает значения и кадр.

**История** (`.lust/history` в папке): каждое изменение сохраняет то, что было до него,
последние 500. `lust_undo` возвращает их.

## Экран — это модуль (`src/screen.rs`, `src/web.rs`)

Ядро знает только **кадр как текст** и **ввод**:

```
size 800 600
clear #000
rect 25 255 10 90 #fff
circle 400 300 8 #ff0
text 330 20 40 #fff 3
```

Lua рисует через `gfx.size/clear/rect/circle/line/text` (только в файлах `draw/`) и читает
`input.down(key)`, `input.pressed(key)`, `input.mouse()`. Модуль показа выводит кадр и
возвращает ввод через `Exchange` (мьютекс, Lua в нём нет).

`web.rs` — один такой модуль: страница на `127.0.0.1` с canvas. Без зависимостей (только
std), отвечает только на запросы с `Host` равным `127.0.0.1` или `localhost` (чтобы чужая
веб-страница не добралась до мира через браузер), принимает не больше 4 КБ ввода за запрос.
Чтобы показывать мир иначе (окно, терминал), достаточно модуля, который читает
`Exchange::frame` и вызывает `Exchange::put_input`; остальное не меняется. Без фичи `web`
он не собирается.

## Безопасность

- ИИ пишет только пути из таблицы выше, внутри папки: без `..`, без других расширений, не
  больше 64 КБ на файл и 2000 файлов.
- Lua мира и драйвера работает в песочнице Lust: нет `io`, `os`, `require`, `load`,
  `pcall`, нет строковых шаблонов; у каждого запуска свой бюджет времени и памяти. Запуск
  драйвера — до 20 с.
- Страница слушает только `127.0.0.1`. MCP идёт через stdio: с `lust dev` говорит только
  программа, которая его запустила.
- Инструмента, подтверждающего операцию роли (`src/mcp.rs`), по-прежнему нет. `lust dev` —
  для разработки, разрешением служит папка; готовая программа даёт ИИ дверь предложений.

## Сколько токенов (замер)

Pong, собранный с пустой папки только через MCP, одна и та же игра дважды:

| | раньше (один `put` на значение) | `lust dev` |
|---|---|---|
| сообщений | 101 | 11 |
| отправил ИИ | 8 839 символов | 4 099 |
| прочитал ИИ | 3 539 | 7 016, из них 6 645 один раз за сессию (список инструментов и справка) |
| исправление в две строки | файл целиком заново, ~1 500 | `lust_edit`, ~70 |
| результат | только числа, без картинки и клавиш | играется в браузере, есть тест |

Примерно 4 символа — один токен, так что вся игра обошлась примерно в 3 000 токенов
содержимого плюс накладные расходы 11 вызовов. Во втором прогоне код был верным с первого
раза (ошибки первого прогона были известны); ошибка теперь стоит один `lust_edit`, а ответ
уже называет файл и строку.

Один такт этого Pong занимает 0,0064 мс; ничего из стороны ИИ в кадре не выполняется.

## Ограничения (честно)

- Справка — около 1 100 токенов, читается раз за сессию; её можно сократить.
- Один проект — один мир. Несколько миров и связи между ними (`src/link.rs`) пока требуют
  Rust.
- Экран простой, 2D: прямоугольники, круги, линии, текст. Картинок и звука пока нет:
  каждое — ещё одна команда кадра и модуля показа.
- `lust dev` крутит мир в том же потоке, что и сообщения MCP: долгий `lust_try` (до 20 с)
  на это время задерживает живые кадры.
- Живой мир `lust dev` не сохраняется между сессиями (у игрового spec нет журнала).
