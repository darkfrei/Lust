# Миры

[English](worlds.md) | Русский

У программы на Lust столько миров, сколько ей нужно, и **все миры одного вида**: сущности,
компоненты, своя песочница Lua, свой код. Различается только то, что мир **хранит** — это его
`Spec` (настройки):

| Настройка | Что значит | `Spec::ledger()` | `Spec::game()` |
|---|---|---|---|
| `journal` | каждое изменение — запись в цепочке хешей (модуль журнала) | да | нет |
| `roles` | права: кто может писать каждый компонент и выполнять каждую операцию | да | нет |
| `undo` | неудачная операция или тик откатывается целиком | да | нет |
| `keep_lua` | глобальные переменные Lua живут от запуска к запуску, как в игровом цикле; верх куска кода выполняется один раз, как его загрузка | нет | да |
| `memory` | память Lua этого мира | 16 МБ | 64 МБ |
| `entities_max`, `values_max` | пределы | 200 000, 2 000 000 | 1 000 000, 4 000 000 |

Две заготовки — только отправная точка, любое сочетание допустимо:

- **Аркада** (арканоид): `Spec::game()`. Хранить нечего, кроме сохранения.
- **Пошаговая стратегия** (Герои 3): `Spec::ledger()` — ради повтора партии и игроков за одним
  компьютером со своими правами; или `Spec { journal: false, ..Spec::ledger() }`, если повтор не
  нужен.
- **ERP**: `Spec::ledger()`.
- **Игра, которая идёт в реальном времени, но не должна терять неудачный тик**:
  `Spec { undo: true, ..Spec::game() }`.

```rust
let kingdom = Host::new()?;                          // Spec::ledger()
let battle = Host::with_spec(Spec::game())?;         // создан сейчас, удаляется после битвы
let menu = Host::with_spec(Spec::game())?;           // интерфейс, свой мир
```

## Журнал — модуль

`src/journal.rs` — это цепочка хешей: `Entry`, `entry_hash`, `verify`. Мир пишет записи, только
если в его настройках есть `journal`. У мира без журнала есть всё остальное: проверка значений по
виду, откат неудачного запуска (если `undo`), снимки для сохранения. `store.rs` пишет журналы и
снимки на диск.

## Два способа хранить компонент

Тип компонента — сущность; его `kind` (вид) говорит, как хранятся значения:

- **текстовые виды** (`text`, `code`, `int`, `bool`, `ref`, `name`, `names`): проверяются при
  каждой записи, попадают в журнал, если мир его ведёт. Для правил, имён, решений, денег.
- **`num`**: число (`f64`) в плотном столбце (разреженное множество: значения одного компонента
  лежат подряд, так что проход по столбцу — это проход по памяти). Никогда не попадает в журнал;
  откатывается вместе с остальным при неудачном запуске (если `undo`); сохраняется в снимках;
  права действуют (если `roles`). Для того, что меняется каждый тик: координаты, скорости,
  здоровье.

Оба живут в одном мире. Пошаговая игра может держать золото как `int` (в журнале), а положение
отряда на экране — как `num`.

## Сущности по имени или по номеру

У каждой сущности есть **имя** и **номер**. `ecs.spawn('ball', {...})` создаёт сущность с именем;
`ecs.spawn({...})` — без имени, она называется `#1`, `#2`, ... (одно имя в мире не выдаётся
дважды). `ecs.id(e)` даёт номер: одно целое число, индекс и поколение, так что номер, выданный
заново после удаления сущности, не достаётся новой сущности по старому id. Каждый вызов `ecs`
принимает имя или номер; номер быстрее для компонентов `num`. `ecs.col(c)` даёт номер столбца —
быстрее, чем имя компонента.

## Код мира

| Сущность | Что это | Когда выполняется |
|---|---|---|
| `op.<name>` | **операция** (`roles`, `params`) | `host.run(role, op, args)`: ввод, ход, команда |
| всё, у чего `system = true` | **правило** | после каждой операции |
| всё, у чего `tick = true` | **тик** | `host.tick(dt)`, в порядке `ord`, с `dt` |
| `view.<name>` | **отчёт**: только чтение, возвращает таблицу | `host.view` |
| любой другой `src` | общий код | `ecs.call` |

`dt` — то, что передаёт программа: время с прошлого кадра или фиксированный шаг. `clock::Clock`
умеет оба:

- `Clock::variable(max_dt)`: один тик на кадр с настоящим временем кадра (`dt` плавает). Плавно;
  то, что нужно большинству игр, которым не надо точно повторять партию. Слишком долгий кадр
  даёт не больше `max_dt`, чтобы после паузы игра не прыгнула.
- `Clock::fixed(step, max_steps)`: равные шаги; кадр выполняет столько, сколько накопилось, но
  не больше `max_steps`, остальное выбрасывает, чтобы один медленный кадр не замедлил и
  следующий. Для физики, которая должна оставаться устойчивой. `Clock::alpha` говорит, где кадр
  между двумя шагами.

**С `keep_lua` верх куска кода — это его загрузка** (как `love.load`): выполняется один раз
(снова, когда код изменился), с правами того запуска, которому он первым понадобился, так что
может создать первые сущности и задать глобальные переменные; функция, которую он вернул,
хранится. **Без `keep_lua`** каждый запуск начинается со свежей копии глобальных переменных, а
верх куска кода — только для чтения: ничего, что скрипт запомнил, не переживает запуск. На этом
стоит песочница учётного мира.

**Системы на Rust:** `host.add_system(name, f)`, где `f: FnMut(&mut World, f64)`; из Lua —
`ecs.run(name, arg)`. Это собственный код программы над целыми столбцами
(`World::column_mut`); он пишет в обход прав, отката и пределов.

## Lua API: таблица `ecs` в каждом мире

Всё, что было раньше (`get`, `own`, `set`, `del`, `kill`, `spawn`, `instantiate`, `with`,
`children`, `exists`, `comps`, `kind`, `call`, `history`, `journal`, `role`), теперь принимает имя
или номер сущности, а для компонента `num` — имя или номер столбца. Новое:

| Вызов | Что делает |
|---|---|
| `ecs.spawn({c = v, ...})` | сущность без имени, её номер |
| `ecs.id(e)`, `ecs.name(e)` | номер, имя |
| `ecs.col(c)` | номер столбца компонента `num` |
| `ecs.count([c])` | сущностей, или сущностей со своим значением `c` |
| `ecs.query(c, ...)` | `n, ids, vals, ...`: сущности, у которых есть все эти компоненты `num`, по новой таблице на компонент, одним вызовом |
| `ecs.read(c, ids, vals)` | `n`: один столбец в две таблицы, которые хранит скрипт (без нового мусора) |
| `ecs.write(c, ids, vals [, n])` | значения обратно, одним вызовом (права и откат действуют) |
| `ecs.add(dst, src [, k])` | `dst += src * k` у каждой сущности, у которой есть оба |
| `ecs.scale(c, k)`, `ecs.fill(c, v)`, `ecs.clamp(c, lo, hi)`, `ecs.sum(c)` | целый столбец |
| `ecs.run(name [, arg])` | система на Rust от программы |
| `ecs.commit({key = value, ...})` | итог для программы (см. ниже) |
| `ecs.tick()` | сколько тиков было у мира |

`history` и `journal` в мире без журнала ничего не дают.

## Из одного мира в другой

Миры независимы. Единственный путь между ними — `link.rs`: мир что-то считает и отдаёт итог
(`ecs.commit{...}`, несколько именованных значений); программа его забирает
(`host.take_result()`) и выполняет в другом мире **как одну операцию роли** (`link::commit_to`):
она проверяется как любая другая операция и пишется в журнал того мира между `from world <name>`
и `end world <name> ok|failed`, если журнал там есть. Любой мир может отдать итог любому другому;
направление ничем не задано.

`Seed` запоминает, что мир прочитал из другого при создании. Пока он считал, другой мог
измениться (игрок продал отряд, король прислал подкрепление); тогда `commit_to` отклоняет итог
как устаревший (`stale: red.units changed while world battle computed`). Дальше решает программа:
создать мир заново по новым значениям или показать человеку.

`examples/battle.rs`: королевство (`Spec::ledger`) и битва (`Spec::game`) на каждый бой. Битва
примерно 1100 солдат длится 3308 тиков; в журнал королевства попадают 4 записи.

## Сохранение

`World::snapshot` содержит все значения, текстовые и `num`, и имена сущностей без имени.
`World::from_snapshot_spec(spec, &snap, entries)` загружает его в мир с любыми настройками
(учётный мир принимает ещё записи журнала после снимка). Глобальные переменные Lua мира не
сохраняются: что должно пережить сохранение, лежит в компонентах. После загрузки верх каждого
куска кода выполняется снова (его загрузка), так что мир заново находит номера своих столбцов и
свои глобальные переменные.

`examples/arkanoid.rs` сохраняет игру посередине, удаляет мир, загружает его в новый и играет
дальше.

## 60–120 кадров без провалов

Провал — это про **худший** кадр: при 60 кадрах в секунду у кадра 16,6 мс, при 120 — 8,3 мс.
`examples/frames.rs` печатает среднее, p99 (99 тиков из 100 быстрее) и самый медленный. Числа —
три прогона на общей облачной машине с 2 ядрами, сборка release; самые медленные значения там
скачут от прогона к прогону. Мерьте на своём компьютере.

| Что (один тик или операция) | среднее | p99 | худший |
|---|---|---|---|
| учётный: одна пустая операция | 0,03 мс | 0,06 мс | 0,2–0,3 мс |
| учётный: 10 000 сущностей по имени, вид `int` (журнал) | 32–36 мс | 44–52 мс | 44–52 мс |
| учётный: то же, вид `num` (права и откат, без журнала) | 11,3–11,6 мс | 12–18 мс | 12–18 мс |
| учётный: записать итог другого мира | 0,03 мс | 0,06 мс | 0,13 мс |
| игровой, 100 сущностей, поштучно из Lua | 0,03 мс | 0,05 мс | 0,25 мс |
| игровой, 10 000, поштучно, имена столбцов | 4,8 мс | 6,8–8,9 мс | 10–16 мс |
| игровой, 10 000, поштучно, номера столбцов | 2,8–2,9 мс | 4,1–5,3 мс | 5,5–9,2 мс |
| игровой, 10 000, поштучно, с откатом | 3,2–3,4 мс | 4,3–5,7 мс | 6–6,8 мс |
| игровой, 10 000, `query`, цикл в Lua, `write` | 0,88–1,0 мс | 0,95–2,3 мс | 1,0–5,1 мс |
| игровой, 10 000, обычные таблицы Lua (вообще без мира) | 0,48–0,50 мс | 0,52–0,82 мс | 0,55–2,7 мс |
| игровой, 10 000, `ecs.add` или система на Rust | 0,006 мс | 0,01 мс | 0,03 мс |
| игровой, 10 000, новая маленькая таблица на сущность (мусор) | 1,5 мс | 1,7–3,9 мс | 2,4–5,1 мс |
| создать мир, 1000 сущностей, два тика, удалить | 1,6–1,7 мс | 1,8–2,2 мс | 1,9–3,7 мс |
| `examples/arkanoid.rs`, кадр | 0,012 мс | 0,03 мс | 0,18 мс |
| `examples/battle.rs`, кадр (около 1100 солдат, 4 тика) | 0,6–0,8 мс | | 2–4 мс |

Что это значит для игры:

1. **Мало сущностей, много тиков — легко.** 100 сущностей поштучно: 0,03 мс на тик.
2. **10 000 сущностей при 120 кадрах — да, но не поштучно.** Поштучно из Lua — около 3 мс на
   тик в среднем и провалы до 9 мс: для 60 кадров хватает, для 120 — впритык. Через
   `ecs.query`, цикл в Lua и `ecs.write` — меньше 1 мс, близко к обычным таблицам Lua. Через
   `ecs.add` или систему на Rust — 0,006 мс. Значит: **одинаковая арифметика для всех сущностей
   уходит в Rust; логика с ветвлениями по сущности — в Lua поверх `query`; `get`/`set` поштучно —
   для немногих особых сущностей** (игрок, босс, кнопка).
3. **Номера, а не имена**, когда поштучно (`ecs.col` и `ecs.id` один раз).
4. **Мусор стоит денег.** Новая маленькая таблица на каждую сущность каждый тик стоит примерно на
   0,5 мс больше на 10 000 и поднимает худшие тики. Храните таблицы от тика к тику (`ecs.read` в
   одни и те же таблицы). Мир с `keep_lua` использует поколенческий сборщик мусора Lua, который
   убирает короткоживущий мусор короткими шагами; `host.gc_step()` собирает шаг в конце кадра,
   если осталось время.
5. **В учётном мире — `num` вместо `int`** для значений, которые часто меняются: примерно втрое
   быстрее, потому что они не идут в журнал и не проверяются как текст.
6. **Создать мир стоит около 1,6 мс** с 1000 сущностей: между кадрами нормально, много за один
   кадр — нет.

Ещё быстрее теперь в каждом мире: **код компилируется один раз** и хранится, пока текст не
изменился (раньше 0,25 мс на запуск для 20 КБ кода, теперь 0,04 мс); **целый столбец переходит**
между Rust и Lua одним защищённым вызовом (`query`, `read`, `write`), а не по одному на значение.

## Что не сделано и что остаётся проблемой

- **Поштучно медленновато.** Около 90 нс на каждый `ecs.get` или `ecs.set` из Lua: цена вызова из
  Lua в Rust через mlua плюс проверка «имя или номер». Меньше не будет без JIT (LuaJIT) или сырых
  функций C.
- **Потоки.** Мир работает в потоке программы; его типы используют `Rc`. Мир в своём потоке (кадр,
  который никогда не ждёт битву) требует настройки `send` у mlua и сообщений между мирами вместо
  общих ссылок. Для многих независимых миров это правильное устройство; это большая переделка.
- **Журнал — модуль исходников, но не сборки.** Мир без журнала не несёт журнал во время работы,
  но `journal.rs` и `sha2` компилируются всегда (снимки тоже используют `sha2`). Сделать его
  функцией Cargo, как `mcp`, можно.
- **Диск в кадре.** Журнал и снимки пишутся в том потоке, который их вызвал; игре нужно вызывать
  их между кадрами.
- **ИИ видит один мир.** Дверь MCP (`mcp::WorldTools`) сделана для одного host; программа с
  несколькими мирами сама выбирает, какой из них видит её ИИ.
- **Одинаковые биты везде** не обещаны (`f64`, `math.sin`, порядок `pairs`). Учётному миру они не
  нужны, потому что он хранит итоги. Программа, которая хочет точно повторять игровой мир, сама
  должна держаться фиксированного шага, целых чисел и постоянного порядка.
- **Система на Rust пишет в обход прав, отката и пределов.** Это собственный код программы;
  неудачный тик в мире с откатом не отменяет того, что сделала в нём система на Rust.
