# ТЗ: модуль `solver` для Lust (решатель ограничений XPBD)

Этот файл единственный источник правды. Он заменяет три прежних ТЗ (основное, цепная линия,
маски слоёв) и список правок к ним. Если что-то здесь расходится с ними, верно то, что здесь.

Написано по коду Lust из GitHub (`darkfrei/Lust`, коммит `8cd0cbb`, 86 тестов). Архив
`D:\Claude\Radost\lust-src.zip` старее, его не брать.

## 0. Слова

- **Вершина** (точка): сущность с координатами, которая движется.
- **Связь**: сущность, которая держит две вершины на заданном расстоянии (балка, трос).
- **Барьер**: неподвижный отрезок, сквозь который вершины не проходят (земля).
- **XPBD**: способ считать физику, при котором сначала все точки двигаются свободно, а потом
  их положения поправляются, пока связи не выполнятся. Устойчив при больших шагах.
- **Подшаг**: кадр делится на несколько маленьких шагов (обычно 16), так точнее.
- **Итерация**: один проход по всем связям внутри подшага.
- **lambda**: сколько «поправки» связь сделала за вызов. Через неё считается сила в связи.
- **compliance** (податливость): 0 значит абсолютно жёсткая связь, больше 0 значит пружина.
- **Колонка**: num-компонент Lust, все значения одного свойства подряд в памяти.
- **Детерминизм**: те же входные данные дают побитово тот же результат.

## 1. Место в Lust

- Папка `src/solver/`, включается признаком сборки (cargo feature) `solver`, который входит в
  `default`, как `mcp` и `web`. Без признака Lust собирается без модуля.
- Подключение: `crate::solver::attach(&host)` в `project::build` рядом с
  `crate::saves::attach(&host)`. Функции попадают в `ecs` через `host.add_to_ecs`.
- В Rust нет слов «мост», «балка», «колесо», «машина». Только вершины, связи, отрезки.
- Раздел 2 файла `docs/roadmap.ru.md` говорит «нет физики... пишется на Lua или отдельным
  модулем». Модуль это и есть «отдельный модуль»; строку надо уточнить (решение N, см. план).

## 2. Как устроены данные в Lust и что из этого следует

Проверено по `src/ecs.rs`:

1. **Каждая num-колонка это отдельный «разреженный набор»** (sparse set): `sparse[индекс
   сущности] -> место`, а значения лежат плотно в `vals`, сущности в `ents`. У каждой колонки
   **свой порядок**. Если сущности создавались со всеми колонками сразу и не теряли их по
   одной, порядок совпадает (так же думает `World::add_cols`). Отсюда два пути:
   - быстрый: `ents` у всех колонок набора равны, проход по срезам подряд;
   - общий: идём по самой короткой колонке, место в остальных берём через `sparse`.
2. **`ref` это текст** (имя сущности в `BTreeMap`). Искать по имени на каждом подшаге
   слишком дорого. Поэтому `node_a` и `node_b` у решателя это **num-колонки с номером
   сущности**, который даёт `ecs.id(e)` (`поколение << 32 | индекс`). `World::index_of(id)`
   проверяет поколение: удалённая сущность даёт `None`, связь пропускается. Так «мёртвая
   ссылка без паники» получается даром. Номер должен быть целым и меньше 2^53, иначе пропуск.
3. **Решатель видит только свои значения сущности**, не значения префаба (`is_a`), как и
   `ecs.query`. Игра должна при создании сущности записать ей все нужные колонки. Это пишется
   в руководство крупно: иначе вершина «без массы» молча не двигается.
4. **Запись мимо прав.** `World::column_mut` отдаёт колонку «для Rust-системы программы, мимо
   прав, отмены и лимитов». Решатель обязан сам:
   - отказать, если `world.read_only` (код `draw/` не может вызвать физику): ошибка `readonly`;
   - сохранить колонки для отмены, если мир ведёт отмену (`spec.undo`), и проверить право
     записи, если мир ведёт роли. Для этого в `ecs.rs` добавить **один** метод
     `pub fn touch_column(&mut self, col: usize) -> Result<(), String>`: проверка права и
     `read_only` плюс `record_column`. Это единственная правка ядра, кроме пункта 5.
5. **Несколько колонок на запись сразу.** `Column` имеет `Default`, поэтому колонку можно
   вынуть: `std::mem::take(world.column_mut(c))`, поработать и положить обратно
   `*world.column_mut(c) = col`. Между «вынуть» и «вернуть» нет ни одного `?`, `return` и
   паники: математика ничего не возвращает с ошибкой. Для записи по индексу сущности в
   общем пути добавить в `Column` метод `pub fn get_mut(&mut self, index: u32) ->
   Option<&mut f64>`.
6. **После записи** все числа конечны. NaN или бесконечность вершина не получает: если расчёт
   дал не-конечное число, значение не пишется (остаётся старое).
7. **Отмена и снимки.** Возврат колонок при отмене (`Undo::Column`) не меняет порядок. Снимок
   (`snapshot`) при загрузке собирает колонки заново в порядке имён, поэтому порядок обхода
   связей после загрузки может стать другим, и результат через много шагов разойдётся в
   последних знаках. Это допустимо и пишется в документацию. Требование детерминизма:
   один и тот же мир (вместе с порядком колонок) даёт один и тот же результат.

## 3. Колонки

Все num. «Нужна» значит: сущность без неё не участвует. «Можно» значит: без неё берётся
значение по умолчанию. «Пишет» значит: решатель записывает, если колонка у сущности есть.

### Вершина
| Колонка | | Смысл |
|---|---|---|
| `x`, `y` | нужна | положение |
| `old_x`, `old_y` | нужна | положение на прошлом подшаге (скорость = разница) |
| `inv_mass` | нужна | 1/масса; `0` закреплённая вершина, `<0` или NaN тоже как `0` |
| `radius` | можно, `0` | радиус для столкновений; `0` значит не сталкивается |
| `layer` | можно, `1` | в каком слое (битовый флаг) |
| `mask` | можно, `1` | с какими слоями сталкивается |
| `contact` | пишет | `1`, если в этом вызове упёрлась, иначе `0` |
| `contact_nx`, `contact_ny` | пишет | нормаль последнего упора |

### Связь
| Колонка | | Смысл |
|---|---|---|
| `node_a`, `node_b` | нужна | номера вершин (`ecs.id`) |
| `rest_len` | нужна | длина, которую держит связь |
| `compliance` | можно, `0` | податливость |
| `mode` | можно, `0` | `0` равно, `1` не длиннее (трос), `2` не короче (распорка) |
| `lambda` | пишет | накопленная поправка за последний вызов |
| `force_max` | пишет | наибольшая сила с тех пор, как Lua её обнулил |
| `layer` | можно | есть колонка: ребро твёрдое для `project_edges` |
| `catenary_a`, `catenary_x0`, `catenary_y0`, `sag` | пишет | форма провисания (раздел 4.7) |

### Барьер
| Колонка | | Смысл |
|---|---|---|
| `x1`, `y1`, `x2`, `y2` | нужна | концы отрезка |
| `friction` | можно, `0` | трение 0..1 |
| `layer` | можно, `1` | слой |

Колонки называются ровно так. `mode`, `layer`, `mask` хранятся как f64; решатель округляет
(`round`), `layer`/`mask` приводит к `u32`.

## 3а. Слои столкновений (договорённость для игр на решателе)

Пара «вершина P, барьер S» проверяется, только если `(P.mask & S.layer) != 0`. Слой самой
вершины (`layer`) нужен запросам и `ecs.project_points` (кто с кем из точек сталкивается). Барьеры:
отрезки (`x1..y2`, колонка `layer`, по умолчанию 1) и рёбра, то есть связи с колонкой `layer`.
**Связь без колонки `layer` никогда ни с чем не сталкивается** (обычная балка, трос). Принятые
биты (игра вправе выбрать другие):

| Бит | Что | Кто сквозь него проходит |
|---|---|---|
| 1 | сплошная земля (отрезки) | с ней сталкиваются шарниры моста (`mask = 1`), колёса и корпус |
| 2 | полусплошная земля (эстакады, фоновые рампы; отрезки) | шарниры и тросы проходят, колёса и корпус едут |
| 4 | дорога (рёбра с `layer = 4`) | шарниры не сталкиваются, колёса и корпус едут по ней |

Шарниры: `radius > 0`, `layer = 8`, `mask = 1` (бьются только о землю, между собой не сталкиваются и колёса сквозь них проходят).
Колёса, корпус и шары: `radius > 0`, `layer = 16`, `mask = 23` (земля 1, полусплошная 2, дорога 4 и другие колёса 16).
Для `ecs.project_points` слой точки теперь важен: пара сталкивается, только если маска каждой пропускает слой другой.
Гарантия: колесо, корпус или шарнир не оказывается под барьером (землёй, полусплошным,
дорогой): если пара пересеклась, вершина всегда выталкивается на ту сторону, с которой пришла
(для ребра сторона определяется по его прошлому положению, поэтому дорога, поднявшаяся сквозь
колесо, поднимает колесо, а не проваливается под него).

Подвеска машины не требует нового примитива: корпус это две вершины с радиусом (`mask = 7`),
жёстко связанные друг с другом; колесо связано с «своей» точкой корпуса пружиной (связь,
`compliance > 0`, `mode = 0`, длина равна высоте подвески), а с другой точкой корпуса жёсткой
длинной связью (рычаг): колесо ходит вверх и вниз почти по вертикали относительно корпуса,
пружина амортизирует. Если такой подвески окажется мало, добавить отдельное ограничение
«точка в системе отрезка» (на деле можно, но только по решению N).

## 4. Функции

Все функции проходят по сущностям в порядке плотного массива колонки (детерминированно), без
`HashMap` в цикле, без потоков, без выделения памяти внутри итераций (рабочие буферы
переиспользуются между вызовами и хранятся в замыкании `attach`; на результат не влияют).
Плохие аргументы (не число, NaN, `dt <= 0`, `iterations` вне 1..64) дают ошибку с кодом
`bad_arg: <что>`. Нет нужных колонок в мире: функция ничего не делает и возвращает 0.
Каждая функция возвращает число обработанных сущностей (для тестов).

### 4.1. `ecs.integrate_verlet(dt, gx, gy, damping)`
Для вершин с `inv_mass > 0`:
```
vx = (x - old_x) * damping;  vy = (y - old_y) * damping
old_x = x;  old_y = y
x = x + vx + gx*dt*dt;  y = y + vy + gy*dt*dt
```
Также обнуляет `contact` у всех вершин (контакт относится к одному подшагу).

### 4.2. `ecs.solve_distance(dt, iterations)`
1. Перевод `node_a`/`node_b` в индексы вершин, один раз за вызов. Мёртвые, не целые, равные
   друг другу, без колонок вершины: связь выпадает из списка.
2. `lambda = 0` у всех связей.
3. `iterations` раз по списку:
```
d = |pa - pb|;  если d < 1e-9: пропуск
n = (pa - pb)/d;  C = d - rest_len;  at = compliance/(dt*dt)
W = wa + wb + at;  если W <= 0: пропуск
dl = (-C - at*lambda)/W
mode 1: new = min(lambda + dl, 0);  mode 2: new = max(lambda + dl, 0);  mode 0: new = lambda + dl
dl = new - lambda;  lambda = new
pa += wa*dl*n;  pb -= wb*dl*n
```
   Важно: для `mode` 1 и 2 **не** пропускать связь по условию `d <= rest_len`. Обрезка суммы
   делает то же самое и не даёт тросу дёргаться при `compliance > 0`.
4. `force_max = max(force_max, |lambda|/(dt*dt))`. Lua обнуляет `force_max` в начале кадра
   (`ecs.fill('force_max', 0)`) и после 16 подшагов видит наибольшую силу за кадр. Без этого
   проверка поломки видит только последний подшаг, и порог зависит от числа подшагов.

### 4.3. `ecs.project_segments(iterations)`
Вершина против неподвижного отрезка, жёстко, без отскока. Пара проверяется, только если
`(mask вершины & layer отрезка) != 0`, `radius > 0`, `inv_mass > 0`.
```
q = ближайшая к p точка отрезка;  delta = p - q;  d = |delta|
если d >= radius: пропуск
сторона: по old (где точка была до шага), не по кратчайшему вектору:
  если old по другую сторону прямой, чем p, или d < 1e-9: n = нормаль отрезка в сторону old
  иначе n = delta/d
v = p - old        (до сдвига!)
p = q + n*radius
vn = dot(v, n);  vt = v - vn*n
если vn < 0:  old = p - vt*(1 - friction)
иначе:        old = p - v          (скорость сохраняется, трение не трогается)
contact = 1;  contact_nx, contact_ny = n
```
Отрезок нулевой длины считается точкой. Нормаль отрезка: влево от направления P1→P2.

### 4.4. `ecs.project_edges(iterations)` (нет в старом ТЗ, без неё машина не давит на мост)
Вершина против **подвижного** ребра (связи с колонкой `layer`). Вершина: `x, y, inv_mass,
radius, mask`. Пропуск, если вершина конец этого ребра или `(mask & layer) == 0`.
```
t = clamp(dot(p-a, b-a)/|b-a|^2, 0, 1);  q = a + t*(b-a)
C = |p-q| - radius;  если C >= 0: пропуск;  n = (p-q)/|p-q|  (при нуле: нормаль ребра)
W = wp + (1-t)^2*wa + t^2*wb;  если W == 0: пропуск
s = -C/W
p += wp*s*n;  a -= wa*(1-t)*s*n;  b -= wb*t*s*n
```
Трение как в 4.3, только относительная скорость считается от скорости точки q ребра.
Пишет `contact`, `contact_nx`, `contact_ny` вершины.

### 4.5. `ecs.query_point(x, y, max_dist [, mask])` -> `id, dist` или `nil`
Ближайшая вершина (`x, y`) не дальше `max_dist`. При `mask` только вершины, у которых
`layer & mask != 0`. При равных расстояниях меньший номер.

### 4.6. `ecs.raycast_segments(x, y, dx, dy, max_dist [, mask])` -> `id, hx, hy, nx, ny, t` или `nil`
Первый отрезок-барьер на луче. Направление нормируется. Нормаль смотрит навстречу лучу.

### 4.7. `ecs.update_catenary(gy)` и `ecs.sample_catenary(id, t)` -> `x, y`
Только форма для рисования, без сил. Сила троса уже есть: это связь `mode = 1`. Работает со
связями, у которых есть `catenary_a`; длина троса берётся из `rest_len`.
- `gy` задаёт, куда вниз. Считать в системе «Y вверх»: при `gy > 0` отразить `y` концов, в
  конце отразить `y0` назад и записать `catenary_a` со знаком минус. Тогда рисование всегда
  одна формула `y = a*cosh((x - x0)/a) + y0`.
- Если `xa > xb`, поменять концы местами до расчёта.
- Решать для `u = dx/(2a)`: `sinh(u)/u - 1 = k - 1`, где `k = sqrt(L^2 - dy^2)/dx`. Число
  `k - 1` считать без потери точности: `(L - d)(L + d) / (dx (sqrt(L^2 - dy^2) + dx))`. Для
  малых `u` (меньше 0.1) брать ряд `u^2/6 (1 + u^2/20 (1 + u^2/42 (1 + u^2/72)))` вместо
  `sinh(u)/u - 1`. Функция возрастает и выпукла, поэтому корень зажат в вилке: слева `0`,
  справа `min(sqrt(6(k-1)), 2 ln(2k))` (проверить, что там функция не меньше нуля, иначе
  удваивать). Ньютон от правого края, шаг вне вилки заменяется половиной вилки, до `1e-13`
  относительной точности, не больше 100 шагов. (Прежняя рекомендация «старт `ln(2k) + ln ln 2k`»
  неверна: эта точка левее корня.) Отсюда `a = dx/(2u)`.
- `x0 = (xa+xb)/2 - a*artanh(dy/L)`, `y0 = ya - a*cosh((xa-x0)/a)`.
- Натянут (`d >= L` или `k - 1 < 1e-9`): прямая, `catenary_a = 0`, `sag = 0`.
- Вертикально (`dx < 1e-6`): `catenary_a = 0`, `y0 = (ya + yb - L)/2` в системе «Y вверх»,
  `sag` по этому.
- `sag`: наибольшее отклонение кривой вниз от хорды.
- `sample_catenary`: при `catenary_a == 0` прямая между концами, иначе формула. Для
  вертикального провиса прямая до нижней точки и обратно.
- Колонка `linear_density` (вес на единицу длины делится на `g`, то есть масса на единицу
  длины) у троса: если она больше 0, на концы действует вес троса, см. 4.8.
- `sinh`, `cosh`, `ln` могут отличаться в последнем бите на разных системах. Это допустимо,
  потому что форма в физику не попадает.

### 4.8. `ecs.apply_catenary_load(dt, gy)`
Сила троса на его концы (провисший трос не невесом: он тянет концы вниз и друг к другу).
Для связей с `catenary_a` и `linear_density > 0`, у которых концы это вершины. Форма считается
заново (как в `update_catenary`, колонки не пишутся). Сила `F`, при `g = |gy|`, `s = sign(gy)`,
`rho = linear_density`:
- кривая: `H = rho*g*|a|`, не больше `20*rho*g*L`. Левый конец (меньший `x`) получает
  `(H, -s*H*sinh(ul))`, правый `(-H, s*H*sinh(ur))`, где `ul`, `ur` это `(x - x0)/|a|` концов.
  Сумма вертикальных составляющих равна весу троса `rho*g*L` вниз, горизонтальные тянут концы
  навстречу друг другу;
- вертикальный провис: конец получает `rho*g*(длина дуги от него до нижней точки)` по `gy`;
- натянут: каждый конец получает половину веса по `gy`.
Применение: `x += w * F * dt^2` для вершины с `inv_mass = w > 0` (так же, как тяжесть в Верле).
Нулевая плотность или `gy == 0` ничего не делает. Это сила только троса на свои концы; масса
самого троса в инерции узлов не участвует. Порядок в подшаге: после `integrate_verlet`, до
`solve_distance`. Когда трос натянут до длины, остальное делает связь `mode = 1`.

## 5. Порядок вызова в игре (для руководства)

```lua
ecs.fill('force_max', 0)
for i = 1, 16 do
  ecs.integrate_verlet(dt/16, 0, 980, 0.999)
  ecs.apply_catenary_load(dt/16, 980)
  ecs.solve_distance(dt/16, 1)
  ecs.project_edges(1)
  ecs.project_segments(1)
end
ecs.update_catenary(980)
```
16 подшагов по одной итерации обычно жёстче и устойчивее, чем 4 по 4, при той же цене.

## 6. Производительность

- Один вызов из Lua на всю функцию, а не на сущность.
- Колонки ищутся по имени один раз за вызов (`World::col`).
- Сравнивать квадраты расстояний, `sqrt` только когда нужно.
- Проверки границ: один `assert_eq!` длин срезов перед циклом.
- Без новых зависимостей (`CLAUDE.md`). Без `unsafe`.
- Мера (этап 9): 2000 вершин, 4000 связей, 200 отрезков, 16 подшагов: кадр меньше 4 мс в
  release на машине N. Время внутри функций идёт в бюджет такта (`run_ms`); если не влезает,
  `world.lua` поднимает бюджет.
- Сетки нет (решение при работе над кодом): перебор «каждая вершина против каждого отрезка»
  с отсевом по ограничивающим прямоугольникам (результат от отсева не меняется). Сталкиваются
  не только колёса, но и шарниры моста (радиус больше 0, они упираются в землю), то есть
  сотни вершин против десятков отрезков: примерно 50 тысяч дешёвых отсевов на подшаг, это
  доли миллисекунды. Если когда-нибудь пар станет в сто раз больше, сетку добавить в
  `contact.rs`.

## 7. Тесты

На Rust (`src/solver/tests.rs`):
1. Свободное падение: после n шагов `y` совпадает с формулой Верле точно.
2. `inv_mass = 0` не двигается ни от гравитации, ни от связей.
3. Связь `compliance = 0`: после 50 итераций `|d - rest_len| < 1e-9`.
4. `mode = 1` короче `rest_len` не действует; длиннее тянет. `mode = 2` наоборот.
5. Удалённая вершина (`ecs.kill`): связь пропускается, без паники.
6. Круг падает на отрезок с высоты: никогда не ниже `radius` минус 1e-9; быстрый круг
   (смещение за подшаг больше `radius`) тоже не проходит насквозь.
7. Маска: `mask & layer == 0` проходит насквозь, иначе стоит.
8. `project_edges`: тяжёлая точка на ребре между двумя лёгкими узлами: узлы уходят вниз,
   сумма импульсов сохраняется.
9. Цепная линия: длина дуги (Симпсон, 2000 отрезков) равна `rest_len` с точностью 1e-5 для
   `gy > 0` и `gy < 0`, для `xa > xb`, для `k = 1.0001` и `k = 50`, для вертикали.
10. `read_only` мир: ошибка `readonly`, данные не изменились.
11. Мир с отменой: упавший такт возвращает `x` к прежним значениям.
12. (убран: сетки нет)
13. Детерминизм: два свежих `Host` с одной и той же сценой на Lua, по 200 тактов, все
    колонки побитово равны. И третий: снимок мира после 100 тактов, `World::from_snapshot`,
    ещё 100 тактов на обоих; сравнить и записать в отчёт, равны ли (см. 2.7: не обязаны).

Проект Lua (`examples/solver/`): маленькая сцена (висячий мост из 10 звеньев, круг на нём,
отрезок земли) и `test/scene.lua`: после 300 шагов (`step`) круг выше земли, мост цел,
`force_max` у звеньев больше 0. В сценарии проверки нет снимков, поэтому детерминизм

## 4.9 Дополнение: капсулы, круг с кругом, тела, пути (сделано)

Движок после этого не правится, поэтому всё нужное для игр добавлено в решатель абстрактно: только точки, звенья, барьеры и числа.

- **Капсулы.** У стенки (`x1..y2`) и у ребра (`node_a/node_b/layer`) есть необязательный столбец `radius` (толщина, по умолчанию 0). Точка держится на расстоянии `её radius + radius барьера`. Точка с `radius = 0` по-прежнему не сталкивается ни с чем.
- **`ecs.project_points(iterations)`.** Круглые точки (`radius > 0`) отталкиваются друг от друга. Условия пары: маска каждой пропускает слой другой, у них не одинаковый ненулевой `group`, и их не соединяет звено. Неподвижная точка (`inv_mass = 0`) работает как препятствие. Скорость сближения гасится, отскока нет. Порядок обхода фиксирован (по x, при равенстве по номеру).
- **`group`.** Необязательный числовой столбец у точки и у ребра. Точки и рёбра одной ненулевой группы не сталкиваются между собой. Так строится жёсткое тело: точки, жёсткие звенья (стороны и диагонали, `mode 0`, `compliance 0`), рёбра по контуру, у всего один `group`. Замкнутый многоугольник, круг и капсула получаются без нового типа.
- **`ecs.path(from, to [, cost])`.** A* по звеньям как по неориентированному графу. Возвращает список id точек от начала до конца и стоимость, либо `nil`. `cost`: 0 длина звена сейчас (по умолчанию, с прямой линией как подсказкой), 1 его `rest_len`, 2 по единице за звено.
- **`ecs.distances(from [, cost])`.** Дейкстра: возвращает два списка, id достижимых точек и расстояния до них.
- **Известные пределы.** Нет столкновения «ребро с ребром»: тонкие тела надо делать с `radius` у вершин. Точка не защищена от прохода сквозь тело, если за один шаг пролетает дальше его толщины. Трения между точками нет. Концы звена, связанного звеном пары, не сталкиваются друг с другом по определению.
- **Свой коэффициент затухания у точки.** Необязательный столбец `damping` (число от 0 до 1, доля скорости, которая остаётся за шаг). Если он есть и в этих пределах, `ecs.integrate_verlet` берёт его вместо общего `damping` вызова; иначе общий. В примере шарниры 0,996, колесо 0,984 при общем 0,999.
- **Минимальное провисание троса.** Необязательный столбец `min_slack` у троса (доля хорды, по умолчанию 0,001; 0 даёт прежнее поведение). Трос с весом не бывает идеально прямым: его длина для расчёта формы и сил берётся не меньше `хорда / (1 - min_slack)`. Раньше при `хорда >= длина` форма считалась `Straight` и сила на концы скачком менялась с очень большой (тянет вверх и внутрь) на половину веса вниз, из-за чего у «натянутого» положения была ловушка, которую держала только связь. Теперь сила на концы меняется плавно и тянет концы к настоящему равновесию. Значение задаёт программа, решатель его не выбирает.
- **Нагрузка троса.** Необязательный столбец `tension` у троса: `ecs.update_catenary` пишет в него натяжение (длину силы на тот конец, что тянет сильнее). У звена-связи нагрузку даёт `force_max`. Прочность (`strength`) решатель не знает и не использует: её задаёт программа и сравнивает с нагрузкой сама (в примере раскраска от зелёного к красному, без обрыва).
- **Трение против поворота: `ecs.damp_angular(spin, bend)`.** Звенья не тела и у них нет угла, поэтому трение сделано над скоростями точек (`x - old_x`), через сдвиг `old_x`, `old_y`; вызывается после `solve_distance` в каждом подшаге. Две доли за вызов (0 ничего, 1 всё): `spin` гасит поворот звена (часть относительной скорости концов поперёк звена, делится по обратным массам, закреплённый конец не двигается), `bend` гасит поворот одного звена против другого в шарнире (по две соседние связи у точки; скорость поворота = cross(d, v_конца - v_точки) / |d|^2). Доля `bend` делится по моментам инерции концов (|d|^2 / w), и точка шарнира принимает обратный импульс, поэтому сумма импульсов и момент сохраняются и энергия только убывает. Без этого обратного импульса цепь получала лишний толчок и со временем «уходила» (проверено на примере: нагрузки росли выше прочности). Необязательные столбцы: `ang_damping` у звена и `bend_damping` у точки (число 0..1, иначе берётся значение вызова). Значения задаёт программа, решатель их не выбирает. В примере 0,005 и 0,05: дрожание дороги подвесного моста на порядок меньше, ферма почти не дрожит.
